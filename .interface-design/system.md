## 2026-10-26 지게차·사람 추적 영상 영역

- 영상 점검은 영상 하나를 중심에 둔다. 카메라 미리보기·실시간 관측·구간 기록은 같은 `MotionStage` 영역에서 전환하고, 프레임 카드 목록을 세로로 늘어놓지 않는다. 데스크톱 높이는 최대420px이고, 좁은 화면에서는 프레임 비율을 유지한다. 컨트롤·위험 요약은 넓은 화면에서 오른쪽 열, 좁은 화면에서는 영상 아래에 둔다.
- 오버레이 SVG는 관측값 `width×height` viewBox를 쓰고 이미지와 같은 상자에 겹친다. 이미지와 관측값은 함께 교체해 같은 프레임만 그린다. 박스는 ID·종류·탐지%, 실선은 지난 경로, 점선과 점은 예상 경로, 빨간 점선은 최근접 지점과 “N초 후 최근접”을 표시한다. 지게차 `--ks-log-warn`, 사람 `--ks-log-info`, 근접 `--ks-log-error`.
- 위험 문구는 쌍마다 한 줄이다. 거리는 사람 키 배수이고 시간은 최근접 추정 시점이다(충돌 시각·미터 아님). NO_PAIR·UNKNOWN은 안전 판정으로 표시하지 않는다. “실시간” 배지는 RUNNING 상태에서 5초 안에 새 프레임이 들어왔을 때만 표시하고, 오류·지연은 마지막 프레임을 유지한 채 “지연 · 사유”로 표시한다.
- 영상 원본은 기존 `KsSelect` 하나에서 고른다. `KsOptionGroup`으로 녹화 장면(원본 영상별: HSE 실제 사고·지게차 급회전·지게차 사고 CCTV, `scenes.json` 순서) → 기존 녹화 영상 → 카메라 순으로 묶고, 장면은 “제목 · N초”로 보인다. 큰 카드나 별도 버튼 목록은 만들지 않는다. 녹화 장면은 “녹화 영상 · 실시간 분석”, 그 밖의 RTSP 장치는 “카메라”로 표시하고, 원본 URL·원본 프레임 구간은 “원본·Mapper” 접힘 안에 둔다. 원본을 바꾸면 끝난 세션의 기록·오버레이를 영상 영역에서 내리고 그 원본의 미리보기를 보여준다. 첫 화면은 명시된 `session` 또는 진행 중인 세션만 연다. 실시간 분석은 구간을 기다리지 않고 표시되며, 10초 구간은 저장 단위라는 문구를 컨트롤 아래에 둔다.
- 실시간은 1초 간격으로 겹치지 않게 조회하고 한 번에 프레임 1장만 읽는다. 보관 범위를 넘어 404가 나온 프레임은 건너뛴다. 해제·화면 전환·중지 시 요청을 중단하고 URL을 해제한다. 기록 재생은 한 장씩 보여주며 이전/재생·일시정지/다음/슬라이더와 프레임별 위험 눈금을 제공한다. 프레임은 최대2장씩 불러오고 사용자가 이동한 프레임을 먼저 읽는다. 사용자가 고른 구간은 폴링해도 바뀌지 않는다.

동일 토큰·폭·44px 컨트롤을 사용하며 Profile/장치 메뉴는 실제 구현 경로만 연결한다.
등록/상세/최근 이력/Node 관측을 semantic section/table/form으로 표현한다.
Device의 데이터 출처와 연결 상태를 분리하고 Node allocatable은 잔여 자원으로 표시하지 않는다.
연결 해제는 화면 내 확인 후 실행하며 이력 보존을 설명한다. 원시 JSON은 접힌 details에 둔다.
Kubernetes 비활성/실패로 관측이 없으면 빈 목록, 60초 경과 시 관측 만료로 표시한다.

## M3 워크플로·실행 요청 화면 확장

기존 색·폭·간격·native form/table을 유지한다. 발행 버전의 읽기 전용 JSON과 새 DAG 입력을 구분한다.
Run 요청 키를 명시적으로 표시하며 재전송과 새 실행을 사용자가 선택한다.
Task/Attempt 상태는 실제 응답을 표시하고 하위 대기·건너뜀·취소를 성공과 구분한다.
취소는 화면 안에서 확인하고 독립 분기 보존·전체 실행 취소의 범위를 설명한다.
초기 실행 요청 저장과 실제 Runner 실행을 구분하며 미구현 실행 성능·결과는 표시하지 않는다.

## M4 결과 조회 확장

작업 상세의 Attempt 아래에 검증된 결과를 배치한다. 빈 결과·저장소 오류·확정 결과를 구분한다.
출력 포트/크기/형식을 기존 semantic table로 표시하고 긴 결과 ID·체크섬·고정 버전은 접힌 details에 둔다.
기존 색·간격·digest 줄바꿈을 재사용하며 파일 URL이나 임의 다운로드 동작을 만들지 않는다.

## M5 재시도 정책

기존 실행 요청 form에 최초 포함 최대 횟수를 두고, 2회 이상이면 대기 시간·허용 기간·오류 선택을 펼친다.
오류는 기존 native checkbox/fieldset과 44px label을 사용한다. Run 상세는 저장된 정책과 RETRY_WAIT,
불변 Attempt 이력을 함께 보여 준다. 기존 spacing/color/table을 재사용하며 새로운 시각 체계는 만들지 않는다.

## M6 VD 등록·원본 연결

기존 색·간격·native form/table·연결 패널을 재사용한다. VD 등록 상태와 실제 런타임 Ready를 구분한다.
원본 키/Device ID를 이름 있는 입력 행으로 편집하며 현재 연결과 보존된 연결 이력을 따로 표시한다.
revision 충돌 시 입력을 유지하고 새로고침을 제공한다. 논리 해제는 화면 안에서 확인하며
VD ID·연결 이력·원본 Device가 보존됨을 설명한다. 새로운 색·레이아웃 토큰은 추가하지 않는다.

## M6 VD 실행 상태

VD 상세의 실행 패널은 현재 준비 상태를 먼저 표시하고 세대·노드·ID를 기존 dl로 배치한다.
시작/교체/종료는 화면 안 확인·동일 키 재전송을 사용한다. 작업 이력은 기존 history-list,
과거 세대/연결은 details로 펼친다. 3초 갱신과 조회 실패·lease 만료를 구분하며 새로운 토큰은 추가하지 않는다.

## M9 관리 요청 감사

운영자가 변경 요청의 주체·HTTP 응답·미확인 결과를 찾는 읽기 전용 화면이다. 기존 회색/흰 패널·
그래파이트 본문·녹색 링크·경계선 깊이·4px 간격·44px 버튼을 재사용한다. 최근 요청 표를 중심에
두고 계정/응답/접수 시각을 비교하며 ID 조회와 상세는 아래에 둔다. 결과 미확인은 오류나 성공
색상으로 추정하지 않고 설명을 표시한다. 상세 JSON은 접힌 details, 모바일 표는 내부 스크롤이다.

## 실제 장비·워크플로 시각 편집

노드 표에 vendor resource 기반 GPU·NPU 총량을 표시한다. 공유 GPU 슬롯과 실제 장치 수를 구분한다.
SERVICE 설정과 작업별 실행 위치는 관측된 노드 이름·아키텍처·가속기 종류를 함께 보여 준다.
ReactFlow 캔버스는 기존 회색/흰색·녹색·얇은 경계선을 사용하고 실제 Profile의 입력/출력 포트를 연결한다.
선택 노드 편집·연결 삭제·DAG 반영·버전 발행·실행 단계를 구분하며 준비 상태를 임의의 녹색 표시로 만들지 않는다.

## 관리 화면 연결

로그인 폼 없이 서버 연결과 오류·재시도만 표시한다. Profile에서 장치·VD·서비스 실행으로 이동하고
UUID 대신 이름·버전을 선택한다. Builder 편집은 단일 DAG 상태에 즉시 반영한다.

배치 정책과 관측된 실제 노드·Pod를 구분하고 고급 STREAM/전환 설정은 접힌 details에 보존한다.

## 2026-10-07 Mapper 센서 등록

- 센서 탭의 기본 원본은 Device/DeviceStatus CRD다. 프로토콜 설치 여부를 실제 지원과 일치시킨다.
- 프로토콜 폼은 이름·host/port·노드·간격과 property 행을 편집한다. Modbus는 Unit ID/register, OPC-UA는 NodeId, MQTT 입력은 topic/JSON 경로, Virtual은 런타임 경로를 사용한다.
  저장한 property 규격을 재사용하고 연결 테스트는 대상 Edge Mapper에서 수행한다.
- 장치별 native details 목록을 기본 접힌 상태로 표시한다. summary에 이름·상태·프로토콜·측정 항목 수·대상 노드를 두고 클릭/키보드로 연다.
  목록 경계는 기존 line/radius, summary와 내용 여백은16px, 이름14px/600·보조 정보12px를 사용한다. 5초 갱신은 장치 ID key를 유지해 펼친 상태를 보존한다.
- 펼친 장치에서 측정 항목마다 별도 표 행으로 최신값·수집 시각·ONLINE/OFFLINE을 표시한다.
  실패 시 마지막 조회 표시와 UNKNOWN을 사용하며 stale 값을 새 값으로 표시하지 않는다.
- 각 행의 항목 삭제는 해당 property만 제거하고, 펼친 장치의 관리 영역에서 장치 삭제는 전체 등록을 제거한다.
  확인은 해당 행 또는 장치 관리 영역 안에서 표시하며 마지막 항목이면 장치 등록도 삭제된다는 안내를 포함한다.
  확인 시 확인 버튼, 취소 시 원래 삭제 버튼, 성공 시 완료 메시지로 초점을 이동한다.
- NEXUS 기존 토큰·native details/form/table을 재사용한다. 저장 오류는 입력을 보존한다.

- Serial JSON·Sense HAT 등록은 Host/Port 대신 장치 경로·소스 Device ID를 사용한다. Serial은 baud rate·프레임 sensor·JSON 경로를 편집한다. Arduino raw 값과 물리 단위를 구분하고 기존 property 행 표를 유지한다.

- 기존 장치의 항목 추가는 펼친 장치의 관리 영역에서 열고 저장 규격 중 미등록 항목을 선택한다.
  추가 form은 해당 장치 안에 표시하고, 편집 중인 장치는 검색 필터에서도 유지해 입력을 보존한다.
  노드·프로토콜·기존 연결 사용을 먼저 표시하고 템플릿의 세부 매핑은 native details로 접는다.
  직접 입력과 개별 항목 수정은 동일 property 필드 편집기를 사용한다. 새 장치 등록과 이름을 구분한다.
  취소는 해당 장치의 항목 추가 버튼, 검색 필터로 그 장치가 숨겨지면 새 장치 등록 버튼으로 포커스를 이동한다.
  성공은 완료 메시지, 서버 오류는 입력을 보존하며 alert로 포커스를 이동한다.

- 기존 장치의 수정은 각 측정 행의 `항목 수정`에서 한 항목만 열고 `항목 저장`으로 적용한다. 전체 properties 편집 버튼은 제공하지 않는다.
  이름은 Workflow 식별자이므로 readOnly이며 값 위치·자료형·단위·배율·보정값은 편집한다.
  5초 갱신과 검색 중에도 편집 입력을 유지한다. 취소는 해당 행의 수정 버튼, 검색으로 숨겨지면 새 장치 등록 버튼에 포커스를 돌려준다.
  서버 오류 시 입력을 보존하고 alert에 포커스를 옮기며 저장 성공은 status에 알린다.

## 데이터 저장소·처리 정의 버전

- 기존 NEXUS 토큰·44px native controls·registry-table/table-scroll·continuous-history-chart를 재사용한다.
