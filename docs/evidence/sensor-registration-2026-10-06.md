## 요구와 결정

사용자가 웹 센서 등록을 요청하고 기존 백엔드 기능 여부를 물었다. 기존 코드는 inventory,
측정값 조회, 명령 실행만 제공했으며 등록 API는 없었다. 기존 미커밋 기능을 보존하고
SensorRegistrationSource → EdgeXSensorRegistration → Service/Controller를 추가했다.

임의 장비 자동 발견이 아닌 지원 센서의 수동 입력 등록이다. 현재 배포된 Arduino6채널과
Sense HAT6그룹의 서비스·프로필을 실조회해서 등록 항목을 제공한다. 임의 URL·프로필 업로드·
프로토콜 JSON·수집기 설치·펌웨어 변경은 제공하지 않는다. 같은 물리 연결의 중복 채널을 거절하고
동일 이름·설정 재요청은 기존 등록을 반환한다. 생성 뒤 설정을 읽어 확인하며 운영 상태와
실측 수신 성공을 혼동하지 않는다. 등록의 영속 원본은 EdgeX DB이고 Git YAML은 자동 수정하지 않는다.

기존 CSRF·동일 출처 프록시·요청 감사 경로를 사용한다. 공개 OpenAPI와 생성 타입을 갱신했다.
UI는 기존 NEXUS 토큰·native form·sensor-detail 패널을 재사용하며 기존 센서 상세 기능을 보존한다.
등록 후 inventory 캐시를 무효화하고, 실패 시에도 불확실한 등록이 조회되도록 다시 읽는다.

## 검증

최종 관련 백엔드 테스트31개: 실패0·오류0·skip0.

- 실제 운영 EdgeX를 새 어댑터의 `catalog()`로 읽기 전용 조회: 지원 항목12개 확인.
- HttpServer fixture 시험: 실제 Java HTTP 직렬화/응답 파싱, 단일 채널 생성, 동일 요청 재조회,
  이름·물리 연결 중복, 경로/속도/종류 검증, 잘린 목록 거절, Sense HAT 고정 버스,
  커밋 이후 응답 실패와 명시적 재요청 확인. 운영 등록을 생성한 시험이 아니다.
- MVC: CSRF 거절,201/200,409/502와 no-store 응답. 서비스: 비활성503, 성공·결과 미확인 시 캐시 무효화.
- 프록시 Node 시험2개: 기존 조회/명령 경로와 신규 등록 경로, JSON·세션·CSRF 전달,
  외부 출처·지원하지 않는 경로·비JSON·64KiB 초과 거절.
- 프론트 타입 검사·lint·production build 통과. build는 앱 프로세스 재시작이나 배포가 아니다.
- Playwright: 실제 실행 UI에 등록 버튼 표시 및 아직 미반영된 백엔드 API의404 안내 확인.
  등록 옵션/응답만 모의 응답으로 바꾸어409 입력 유지 →201 완료 → 폼 닫기·포커스 복귀를 검증.
  Sense HAT의 읽기 전용 I²C 버스와 Serial 전용 속도 필드 전환 확인.
  데스크톱·390px 모바일 캡처를 확인했고 모바일 문서 가로 넘침 없음.
  `output/playwright/sensor-registration-desktop.png`, `sensor-registration-mobile.png`.

브라우저 검증 중 완료 버튼으로 포커스를 돌릴 때 버튼이 아직 disabled인 문제를 발견해,
등록 처리 종료 렌더 후 포커스를 복원하도록 수정하고 해당 동작을 재검증했다.

## 적용 상태와 경계

운영 센서 등록12개와 실제 수집기 배포를 변경하지 않았다. 실행 중 Spring을 재시작하지 않았으며,
사용자가 새 코드를 재실행해야 신규 등록 API를 사용할 수 있다. 실제 새 물리 센서를 연결한 등록·수신
종합 검증은 수행하지 않았다. 미지원 센서/노드 추가와 분산 동시 등록 조정은 별도 구현이 필요하다.

Semantica 선행 결정은 로컬 그래프에서 조회했으나 MCP 기록 도구가 연결되지 않아 이번 결정을
그래프에 저장하지 못했다. 확정 요구·설계·검증·남은 경계는 이 문서에 기록했다.
