# Remote 시작 허가의 영속 접수 기록

ADR0099는 API worker의 Run 잠금 아래 확인한 시작 권한을 실제 참조 제공자에 전달한다.
참조 제공자는 원래 작업 digest/lease·전환 ID/deadline과 실제 입력을 확인한 뒤,
시작 접수 시각·권한·RUNNING 전이를 같은 SQLite transaction으로 저장하고 계산을 시작한다.
완료 파일로 시작 권한을 추정하던 복구 경계를 위한 독립적인 실행 시점 기록이다.

실제 TLS/SQLite/프로세스의 새7개 `20261004T191945Z-99c8d159`가 통과했다.
전체 회귀의 최종 `20261004T192155Z-4c060e15`는 Python24개와 Java HTTP 제공자 연동13개
PASS다. 다음을 포함한다.

- 동시8개 시작 요청은 실제 계산1개·권한 기록1개이며 다른 권한/권한 생략은 거절한다.
- 실제 늦은 HTTP 본문은 원래 시작 기한과 제공자 fence를 다시 확인한다.
- 잘못된 신원/digest/lease·불완전 전환·null/배열 본문은 실행과 기록을 만들지 않는다.
- 실제 SQLite trigger 오류는 기록과 실행 전이를 원복하고 이후 정상 요청은 한 번 실행한다.
- 기록의 UPDATE/DELETE를 거절하며 원래 기록을 보존한다.
- 시작 접수를 별도 연결로 확인한 뒤 원래 HTTP 응답을 읽지 않고 버려도 계산은 중복되지 않는다.
- 실행 중 프로세스 SIGKILL/재시작은 PROVIDER_RESTART로 끝나며 기록을 유지한다.
- 운영 자격·설치/복구 ID·전체 차단/스레드 종료를 확인한 복구 조회만 기록을 반환한다.
- 이전 DB 업그레이드와 legacy 실행에 시작 기록을 소급 생성하지 않는다.

초기 전체 회귀 `20261004T192109Z-1c7d4ca3`는 응답 유실 시험에서 시작 접수를 관측하지
못해 실패했다. 당시 시험은 TLS 요청을 보내자마자 연결을 닫아 요청 접수와 응답 유실을
구분하지 못했다. 접수를 별도 연결로 먼저 확인한 뒤 응답을 버리도록 시험을 보완했다.
제품의 retry/deadline 조건이나 기다리는 제한은 완화하지 않았다.

공개 API/PostgreSQL/실제 Remote/S3의48개 `20261004T192333Z-a87e3730` PASS다.
Remote worker14개에 일반 부모/자식 실행의 실제 SQLite 기록·작업/digest와 공개 NODE→Remote
전환의 원래 offload ID/deadline·실제 접수 시각 대조를 포함한다. 새 지연 시작 시험은
API가 발급한 허가를 유지한 채 원래 전환 기한이 지난 뒤 양쪽에서 시작을 거절하고,
제공자는 ALLOCATED/기록 없음으로 유지한 다음 공개 취소로 실제 종료한다.
시험 전용 PostgreSQL DB와 MinIO 제거를 확인했다. Kubernetes source는 명시적 fixture다.
단위122개 `20261004T192819Z-56af45a4`, 전체 OpenAPI 생성·MVC/Swagger 계약
`20261004T192914Z-3de1b62b`도 PASS다. 새 CI/배포는 별도로 확인한다.
기존 복구 CLI가 이 기록을 복원 DB 전환 성공에 반영하는 기능, Kubernetes 시작 권한,
실제 외부 제공자·종합 복구 활성화는 별도 수용 대상이다.
