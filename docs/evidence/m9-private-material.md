# M9 정적 키 파일 암호화·복원 검증

2026-10-04, ADR0065. 최종 로컬 근거 `20261004T033214Z-e49bced8`의 원시 결과는
PASS/exit0이며 실제 age v1.3.2와 OpenSSL을 사용한10개 시험을 통과했다.
소스는 합성 TLS 키쌍·Runner 키·저장소 인증 자료4개, 해당 실행의 합계는3,009bytes다.

1. 공개 수신자만으로 백업하고 외부 manifest에 파일 이름/비밀값이 없음을 확인.
2. 원본 파일 디렉터리를 삭제한 뒤 전체 bytes/권한을 복원하고 실제 TLS 공개 키를 대조.
3. 기존 백업/복원 디렉터리 덮어쓰기를 거절하고 내용 보존.
4. 다른 복호화 identity를 거절하고 복원 파일/임시 평문이 남지 않음을 확인.
5. 암호문을 변조하고 외부 checksum을 다시 계산해도 실제 age 인증 복호화에서 거절.
6. 심볼릭 링크·하드 링크·공개 권한 파일·FIFO·identity 링크와 설치 캐시 디렉터리 링크 거절.
7. 상대 경로 이탈·절대 경로·중복 이름·파일/디렉터리 이름 충돌 거절.
8. 실제로 암호화한 악성 내부 archive6종의 경로/해시/추가·중복 entry/링크/압축 거절.
9. 실제 암호화 도중 입력을 변경하면 성공 manifest를 발행하지 않고 임시 평문 제거.
10. native PQ identity/recipient로 같은4개 파일을 암호화·복원하고 전체 내용 대조.

초기 `032237Z-410ff043`은9개 통과 후 PQ 복원에서 실패했다. 도구가 만든77자 compact
identity를 자체 길이 필터가 거절한 것이 원인이었고, 공식 도구가 구조/checksum을 검증하도록
필터 하한을 고쳤다. 수정 직후 `032854Z-3fdf9b40`도10개 PASS였으며 위 최종 근거에는 추가
FIFO/설치 링크 시험을 포함한다. 중간 `033140Z-533fa012`는 기존 개발용 `.tools`의 그룹 쓰기
권한을 신규 검사에서 거절했다. 설치 경로의 소유권/정규 디렉터리/링크 경계를 확인하도록
수정했으며 공유 작업 디렉터리의 권한을 변경하지 않았다.

고정 공식 archive SHA256:

- amd64: `cbe24006683f8eb669266162894b9a522a1af52f2665fbc63a4bb032ed26ac10`
- arm64: `6b8dc4333c53a5a57c9e5834e3a48f92605d7154014cd07269ff3327db5d37f4`

매 실행에서 archive와 실제 도구를 대조했다. 로컬 실행은 amd64이며 arm64 실행 수용은 남는다.
CI scaffold에 설치·실제10개 시험·안전한 요약 업로드를 연결했다. 이 문서 작성 시점에는 새
CI 게이트의 원격 실행을 아직 확인하지 않았다.

운영 키/Secret은 읽거나 교체하지 않았다. 개인 키와 평문 합성 fixture는 Git에서 제외된
소유자 전용 경로에만 두었다. 파일 복원은 작성자 서명 검증이나 서비스 활성화를 뜻하지 않는다.
키 전달/회전·실제 Secret 버전 매핑·broker/장치 journal·결합 복구와 전체 M9 수용은 남는다.
