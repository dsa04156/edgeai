# S3 기존 버전 백업의 스캔 의존성 제거

결합 복구 시험 `20261004T183922Z-a3a941ca`와 `20261004T185026Z-d1e22d8b`가
S3의 원래 버전 복제 대기에서120초를 넘었다. 둘 다 복구 업무 검사를 실행하기 전이며
소유 namespace/DB/API/브로커/스토리지는 제거됐다. 독립2객체 복제
`184420Z-a979e30b`와 작은 복원26개 `184620Z-1eb595e3`는 통과했다.

배경 scanner 속도를 느리게 한 별도 소유 MinIO에서 수정 전 경계를 분리했다.
`20261004T185737Z-e4681f78`은 REPRODUCED: 실제2객체 백업이5.92초 뒤 제한을 넘었고,
소유 rule은 제거됐으며 성공 manifest는 없었다. 시험 서버만 `slowest`로 구성했다.

ADR0098의 소유 target resync 적용 후 `20261004T185831Z-0be128f4`는11개 PASS다.
source/target 모두 같은 `slowest` 설정이다. 실제4개 version ID, 262176bytes와 SHA-256,
TLS·권한·소유 대상/규칙·원본 종료·대상 재시작과 실패 경계를 확인했다.
backup-report의 resyncsStarted는1이며 스캔 주기를 기다리는 조건을 제거했다.
다른 rule ID를 지정한 resync 요청은 기존 설정을 보존하며 거절됐다.
소유 서버 프로세스 종료를 확인했다. MinIO 바이너리는
`a18c259d800694d3d48b5d4d25091b053359be11d8e8c834b8481e445ad52c48`이다.

이 재현은 백업의 scanner 의존성을 증명한다. 앞선 두 실패의 모든 실행 내부 상태를
수집한 것은 아니므로 개별 스캔 경로까지 단정하지 않는다. 동일한44개 결합 시험은
`20261004T185953Z-272d4e46` PASS다. 복원 DB18개·고정 checkpoint/S3 version2개와
소유 자원 정리를 확인했다. 새 원격 CI는 별도로 확인한다.
