# 관리 요청 감사 기록

감사 기록은 관리 API 변경 요청의 접수와 관측한 HTTP 결과를 조회하는 기능입니다.
업무 완료·물리 장치 변경·전체 시스템의 보안 감사를 대신하지 않습니다.

## 조회

Dashboard의 **감사 기록**(`/audit`)에서 최근 요청을 페이지로 조회합니다.
응답 헤더의 `X-EdgeAI-Audit-Id`로 특정 요청을 찾을 수 있습니다.

| API | 역할 |
|---|---|
| `GET /api/v1/audit-requests` | 접수 시각 역순 목록; limit·offset 계약 적용 |
| `GET /api/v1/audit-requests/{auditId}` | 특정 감사 기록 |

기록의 작업·대상·주체·HTTP 상태를 확인합니다. 현재 로그인 없는 요청의 주체를
인증된 개인으로 해석하지 않습니다. 과거 `LOCAL_BASIC`은 해당 시점의 기록입니다.

## 상태 해석

`OUTCOME_RECORDED`는 HTTP 결과가 저장됐다는 뜻입니다. 202라면 실제 작업의 완료를
Run·Task·Operation 또는 외부 시스템에서 확인합니다.

`OUTCOME_UNKNOWN`은 결과가 없다는 뜻으로 처리 중이거나 결과 저장이 실패했을 수 있습니다.
성공·실패를 추정하거나 새 요청으로 무조건 재실행하지 말고 원래 요청 키와 대상 상태를 확인합니다.

## 저장과 실패

관리 변경 요청은 실행 전에 별도 DB 트랜잭션으로 접수를 기록합니다.
접수 저장이 불가능하면 503 `AUDIT_STORE_UNAVAILABLE`로 거절하며 변경을 실행하지 않습니다.
완료 기록 저장 실패는 이미 실행된 변경을 되돌리지 않습니다.

정상 GET·HEAD·OPTIONS는 기록하지 않습니다. 거절 응답 등은 필터의 감사 범위에 따라 기록할 수 있습니다.
수집되는 것은 등록된 operation·route·대상 식별자이며 원문 본문, query, 쿠키, 토큰, 비밀번호를 저장하지 않습니다.

## 범위와 한계

내부 Runner·Device·VD 프로토콜, worker, 직접 DB 수정, 외부 프록시의 모든 행위는 이 관리 감사 범위 밖입니다.
접수·완료 테이블은 수정·삭제로부터 보호하지만 DB 관리자에 대한 외부 변조 방지 증거는 아닙니다.
자동 보관 기간·외부 감사 저장·사용자별 권한의 전체 수용은 별도입니다.
복원 조회 전용 모드에서는 새 감사 쓰기를 끄고 보존된 이력만 조회합니다.
