# 센서·처리 선택으로 가상 장치 등록

기준 커밋: `8763316`. 사용자는 공통 실행 이미지를 마련하고 센서와 처리 기능을 선택해서 가상 장치를 등록할 수 있어야 한다고 요청했다.

- 공통 Processing Engine을 포함한 실행 이미지를 실제 빌드·검증하고 레지스트리에 발행한다. 서버는 실제 발행된 digest와 검증된 아키텍처를 고정한다. 사용자가 이미지나 SERVICE/VD Profile UUID를 입력하지 않는다.
- 기본 등록은 이름·키, 등록된 센서, 숫자 측정 항목, 처리 기능/순서/파라미터, 표본 수와 수신 시간으로 구성한다. 필터, 이동평균, RMS, FFT, 임계값을 기존 엔진 계약으로 제공한다. 센서가 바뀌면 이전 측정 항목을 지운다.
- 서버가 센서 모델, 공통 SERVICE, 처리 템플릿과 원본 바인딩을 자동 연결한다. 내용이 같은 프로필은 재사용하며 기존 VD 생성의 중복 요청·충돌 정책을 따른다. 잘못된 입력은 전체 DB 트랜잭션을 취소한다. 센서/Mapper 리소스를 새로 생성하거나 변경하지 않는다.
- 공통 이미지가 설정되지 않았으면 준비되지 않았음을 명시하고 간편 등록을 막는다. 기존 템플릿·SERVICE 관리 경로는 고급 설정으로 유지한다.
- 기존 NEXUS/native form 디자인을 재사용하며 입력 실패 시 선택을 유지한다. 저장 후 조회 실패는 저장 성공과 구분한다. 모바일에서 페이지 가로 넘침이 없어야 한다.
- 실제 PostgreSQL API 시험, 처리 런타임 컨테이너 시험, 데스크톱·모바일 브라우저, 계약·타입·lint·build와 두 독립 코드 리뷰로 검증한다.
- 이 변경은 운영 클러스터 배포·main 병합·기존 데이터 삭제를 포함하지 않는다. 제공된 아키텍처의 호환 노드에 자동 배치하며 센서의 수집 노드와 실행 노드는 달라도 된다.
