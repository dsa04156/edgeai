## 1 기술 개요와 개발 범위

본 기술은 기존 EdgeAI의 센서, 가상디바이스, 실행 모듈과 워크플로 관리 API를 Kestra 원본 Vue 앱의 탐색과 디자인 시스템에 연결하는 통합 운영 콘솔이다. 노드 및 가속기의 실제 관측값을 신원에 맞게 표시하고 실행 상태, 결과와 감사 기록을 조회한다. Kestra v2.0.6 UI를 사용하며 Kestra 서버와 DB를 설치하거나 실행 엔진을 교체하는 방식은 아니다. [1]

자체 개발 범위는 EdgeAI용 Vue 화면과 라우터 연동, API 프록시 및 세션 분리, 관측 스냅샷과 자원 신원 매핑, 그래프 및 이력 조회, 기존 기능의 입력과 오류 계약 보존이다. Kestra UI와 디자인 시스템, ECharts 및 Prometheus는 기반 소프트웨어이다. DDS 메뉴의 외부 연동 이력이 있어도 DDS 기술과 배포 기능은 이번 등록 범위에서 제외한다.

### 1 1 화면 범위

| 화면 | 주요 연결 기능 |
|---|---|
| 운영 현황과 장치 | 서버 우선 목록, CPU와 메모리, GPU 및 NPU 관측, 센서 관리 |
| 가상 장치와 저장소 | 계산 정의 및 저장 정책, 원본과 결과 그래프 및 이력 |
| 모듈과 워크플로 | SERVICE 버전, DAG 편집과 초안 및 파일 교환 |
| 실행과 감사 | Run, Task, 결과, STREAM 경로와 전환 이력, 감사 ID |

UI에서 실제 등록, 조회, 실행 준비와 성공을 구분하며 데이터가 없는 상태를 임의의 정상값으로 채우지 않는다.

## 2 관측 신원과 자원 표시

### 2 1 메트릭 집계

서버는 기존 Prometheus에 고정된 조회식을 사용하고 브라우저는 서버 API만 호출한다. node-exporter, kube-state-metrics와 장비별 exporter의 관측을 Kubernetes 노드 및 장착 정보에 연결한다. DCGM의 Hostname이 exporter Pod 이름인 경우 이를 실제 노드 이름으로 사용하지 않고 Pod의 노드 배치를 확인한다. [2]

| 자원 | 관측 기준 | 표시 원칙 |
|---|---|---|
| CPU | idle 시계열의 최근 두 수집값 기반 irate | 노드별 백분율, 노드 간 합산 금지 |
| 메모리 | MemAvailable과 MemTotal | 가용 메모리를 제외한 비율 |
| GPU | DCGM, Jetson, Spark 등의 실제 지표 | 장치별 사용률과 제공되는 상세만 표시 |
| NPU | 지원 exporter와 장착 정보 | 장착과 사용률 계측 유무를 구분 |
| 노드 상태 | Ready 조건, 시각과 수집 성공 | 만료 또는 실패를 Ready로 추정하지 않음 |

### 2 2 운영 현황 배치

기본 표는 AI 서버를 우선 표시하고 더보기에서 엣지와 분류 미확인 노드까지 펼친다. CPU와 메모리 막대를 나란히 두고 GPU 및 NPU는 같은 열에서 장치별로 표시한다. 사용률이 없는 장치와 실제 0퍼센트는 구분한다. 공유 슬롯을 물리 GPU 여러 개로 세지 않는다. [1]

운영 표에서는 사용자의 표시 정책에 따라 Intel NPU를 숨기되 원본 계측 데이터는 유지한다. KPI와 전체 노드 상태의 범위는 목록 더보기와 구분한다. 화면 갱신을 빠르게 하여도 exporter의 원래 수집 주기보다 신선한 관측이 생기는 것은 아니다.

## 3 API 계약과 편집 상태 보존

### 3 1 서버 경계

관리 API와 워크플로 API는 고정 origin으로 연결하고 독립 세션 및 CSRF를 보존한다. 원본 계약의 revision, Idempotency-Key와 감사 ID를 전달한다. lossless JSON으로 큰 정수를 보존하고 허용되지 않은 경로나 메서드의 임의 쓰기 전달을 막는다. 현재 별도 콘솔은 13083, 기존 BFF는 13080, 관리와 실행 API는 각각 18080과 18082를 사용한다. [1]

### 3 2 편집 및 파일 교환

DAG 편집기는 그래프와 코드, 입력 선택 및 불변 버전 발행을 연결한다. 브라우저 초안은 워크플로별로 저장하고 복구를 명시적으로 요청한다. 적용 전 JSON과 좌표 및 큰 정수를 보존한다. 파일 불러오기는 현재 그래프나 미적용 코드가 있으면 교체를 확인하고 취소 및 검증 실패 시 현재 내용을 유지한다.

### 3 3 기록 자동 갱신

| 대상 | 갱신 방식 | 조회 상태 보존 |
|---|---|---|
| 실행 목록 및 선택 상세 | 첫 목록 3초 및 선택 상세 자동 조회 | 선택한 Run과 Task 유지 |
| STREAM 경로 | 열린 첫 페이지를 3초마다 조회 | 접기와 일시정지, 이전 페이지에서 중단 |
| 감사 목록 | 첫 페이지 5초 | 선택한 미확정 응답을 함께 갱신 |
| 센서 및 VD 이력 | 5초 자동 조회와 일시정지 | 확대 시각과 이전 원본 표 유지 |

백그라운드 갱신은 화면 전체를 가리는 로딩을 표시하지 않는다. 초기 및 수동 조회는 로딩 상태를 표시한다. 오류 시 마지막 기록을 유지하면서 실패를 알리고 조회 대상 변경 후 도착한 늦은 응답은 버린다. 전환 이력에서는 대상, 상태, 실패와 판단 기준을 먼저 표시하고 checkpoint와 원본 JSON을 펼쳐 확인한다.

## 4 구현 및 검증 결과

### 4 1 시험 결과

| 검증 항목 | 확인 내용 | 시험 경계 |
|---|---|---|
| 관측 집계 | 실제 0, 만료, 일부 누락, 장착 정보와 공유 슬롯 | 기존 API 경계 단위 시험 |
| 세션 및 프록시 | 독립 세션, CSRF, 큰 정수, 멱등 키와 경로 제한 | native 콘솔 HTTP 경계 시험 |
| 파일 교체 | 취소, 같은 파일 재선택, 검증 실패, 좌표와 큰 정수 왕복 | 2026년 10월 19일 공개 UI 회귀 |
| 라이브 기록 | 새 상태, 과거 페이지 고정, 일시정지, 실패 및 복구 | 브라우저 가상 시계와 HTTP fixture |
| STREAM 및 전환 | 세대와 차단 사유, 실행 전환 응답 격리, 정책 없는 기록 | 2026년 10월 20일 브라우저 회귀 |

2026년 10월 20일 native Vue 타입 검사, 기존 native API 경계 시험 27개와 문서 검사가 통과하였다. 전환 이력의 종료 상태 오표시와 정책 요약 누락을 수정한 뒤 Standards 및 Spec 재검토에서 각각 잔여 지적 0건을 확인하였다. 모바일은 메뉴를 접은 390픽셀 화면에서 표시를 확인하였다. [3]

같은 날 실제 API에서는 Run 6개와 Task 12개, 저장 경로 6개를 읽어 확인하였다. 선택한 표본에 전환 이력이 없었으므로 전환 상태의 화면 검증은 fixture에 근거한다. 이 시험을 실제 장비 전환과 모델 실행의 신규 수용으로 표현하지 않는다.

### 4 2 검증의 한계

기존 기능 일부의 누락을 순차 복원한 상태이며 모든 과거 화면과 기능의 동등성 대조를 완료했다는 의미는 아니다. 사용자별 identity 및 RBAC, 운영 포트 통합과 장기 수용은 별도 범위이다. [4]

## 5 개발 기여와 배포 조건

### 5 1 소프트웨어 구성

`dashboard/kestra-native/`는 EdgeAI용 Vue 화면과 API 경계, 관측 및 실행 컴포넌트를 포함한다. `scripts/dev/dev-kestra-native.sh`는 고정 revision의 Kestra 원본 UI를 준비하여 실행한다. 원본 UI revision은 b59444f09be2e44a3b0738452b2e02fc4fe89505이며 Node 24와 npm 11 환경을 사용한다. 원본과 EdgeAI 소스의 기준을 각각 기록하여 다시 만들 수 있도록 하였다. [1][5]

개발 성과는 기존 API와 원본 UI의 연결, 신뢰 가능한 관측의 선별 및 표시, 작업 상태와 편집 데이터 보존, 기능별 관리 흐름의 구현이다. Kestra의 원본 화면 구성과 컴포넌트, Prometheus 및 ECharts 자체의 개발 성과로 기술하지 않는다. 외부 라이선스와 고지는 인수 자료에 유지한다.

### 5 2 적용 및 후속 작업

현재 콘솔은 기존 웹과 API를 보존한 별도 포트로 실행한다. 기본 포트를 바꾸거나 자동 시작 서비스를 설치한 것으로 간주하지 않는다. 서버 설정과 원본 UI 준비, BFF 및 API 연결을 갖춘 뒤 TDP-02의 기동 및 인수 절차를 따른다.

임의 장비의 모델 수용과 실시간 처리 성능은 화면 관측과 다른 시험이다. 만료값과 마지막 성공값을 최신 관측으로 표시하지 않는지, 실패 후 사용자가 현재 상태를 구분할 수 있는지 확인한다. 실제 장비 연결 복구 보류 항목은 새 UI의 성공 표시로 대체하지 않는다.
