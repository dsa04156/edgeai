## 1 기술 개요와 해결 문제

본 기술은 MQTT로 수신한 센서 관측을 InfluxDB에 보관하고 저장 완료와 메시지 승인을 연계하는 수집 경로이다. QoS 1 재전달, 구형 원본과 검증 원본의 중복, 저장소 지연 및 저장 장애를 처리하면서 원래 측정 시각과 출처를 유지한다. 최신 Twin을 주기적으로 읽어 저장하는 방식과 별도로 매 수집 관측을 소비한다. [1]

개발 중에는 MQTT 수신량만 높이면 내부 저장 대기가 쌓이는 문제와 InfluxDB 2.9.1의 동기 DELETE 및 TSI 작업이 서로 기다리는 문제가 관측되었다. 이에 수신과 저장의 수용량을 구분하고 저장 완료 뒤 순서대로 ACK하도록 하였으며 수집 경로의 중복 정리에서 동기 DELETE를 제거하였다. [2][3]

### 1 1 주요 설계

| 항목 | 적용 방법 |
|---|---|
| 관측 식별 | UID, property, 수집 설정, generation, session, sequence 유지 |
| 승인 시점 | 내구 저장 완료 후 QoS 1 수동 ACK |
| 대기 제한 | 수용 상한을 두고 측정 항목별 작업을 분리 |
| 중복 조정 | 검증 원본 우선과 논리 비표시 처리 |
| 조회 | 원본 측정 시각, cursor와 원본 문서를 보존 |

적용 대상은 프로젝트의 센서 원본 수집기와 InfluxDB 어댑터이다. NanoMQ와 InfluxDB 제품 자체를 수정한 기술로 주장하지 않으며, 보장 범위는 브로커의 재전달 조건과 저장소 내구 설정에 의존한다.

## 2 수신과 저장 승인 구조

### 2 1 처리 순서

수집기는 MQTT 관측을 파싱하여 원본 신원을 검사하고 저장 작업의 수용 여부를 결정한다. 같은 측정 항목의 구형 및 검증 원본 조정은 순서를 지키면서 수행한다. 서로 다른 항목의 대기는 분리하여 특정 항목의 지연이 전체 수신을 장시간 막는 상황을 줄인다. [2]

| 순서 | 처리 | 실패 시 동작 |
|---|---|---|
| 1 | 메시지 수신과 규격 검사 | 잘못된 관측을 유효 원본으로 승격하지 않음 |
| 2 | 저장 수용량 확보 | 처리 한도 안에서 대기 및 backpressure 적용 |
| 3 | 측정 항목별 조정과 Influx 쓰기 | 저장 실패를 완료 처리하지 않음 |
| 4 | 완료 digest 기록 | 실제 저장 성공 항목만 캐시에 추가 |
| 5 | 연결별 FIFO ACK | 앞선 미완료 수신을 넘어 승인하지 않음 |

최종 수집 경로는 수용 상한 64개와 수동 ACK를 유지하고 가상 스레드 및 공정 잠금으로 측정별 대기를 분리하였다. 최근 4,096개의 동일 경로 및 payload digest는 이미 완료한 재전달의 중복 쓰기를 줄이는 메모리 캐시이다. 프로세스 재시작 후에는 기존 원본 신원으로 저장을 다시 확인하며 캐시를 영속적인 중복 제거 원장으로 취급하지 않는다. [2]

### 2 2 내구성 경계

프로토콜의 PUBACK과 응용 처리 완료 ACK는 역할이 다르다. 원본 수집의 MQTT ACK는 저장 완료에 연결하지만 워크플로 STREAM 소비자의 계산 완료까지 의미하지 않는다. 저장 실패 중 무제한 수신과 메모리 축적을 허용하지 않으며 재전달 가능 범위는 브로커 큐, 영속화와 세션 만료 설정에 제한된다.

## 3 관측 식별과 중복 조정

### 3 1 신원과 시각

검증 관측은 source generation, session과 sequence를 유지한다. 같은 원본 시각에 서로 다른 sequence가 있으면 별도 관측으로 저장한다. Influx 내부 point 시각의 1ms 미만 부분은 식별에 사용될 수 있으나 공개 API의 observedAt은 원래 측정 시각이다. 수치와 원본 문서를 보존하여 조회에서 임의 평균이나 보간을 원본으로 바꾸지 않는다. [1]

구형 DataModel에는 sequence가 없어 개별 측정의 구분에 한계가 있다. 같은 UID, 항목, 설정, 원본 시각, 타입과 값을 가진 구형 및 검증 관측이 함께 오면 검증 관측을 우선한다. 값이나 sequence가 다른 관측까지 합치지 않는다.

### 3 2 논리 비표시 처리

기존 중복 구형 point를 즉시 DELETE하던 경로는 빈 문서와 archive_visible=false를 기록하는 방식으로 변경하였다. 신규 원본에는 archive_visible=true를 기록한다. 원본 목록과 이력은 빈 문서를 제외하고 차트는 비표시 항목을 제외한다. [2]

| 항목 | 변경 후 의미 |
|---|---|
| 구형 중복 문서 | 조회에서 제외하는 논리 표시 적용 |
| 기존 typed field | bucket 보관 기한까지 물리적으로 남을 수 있음 |
| 원본 조회 API | 표시 조건을 적용한 유효 원본 반환 |
| raw Influx 직접 조회 | 동일 표시 조건을 직접 적용해야 함 |

이 처리는 InfluxDB DELETE 결함 자체의 수정이 아니다. 동일 수집 경로에 동기 DELETE를 다시 도입하면 재발할 수 있다. 외부 소비자가 원시 Influx 필드를 직접 읽는 경우 논리 표시 조건과 데이터 보존 정책을 함께 전달해야 한다.

## 4 구현 및 시험 결과

### 4 1 관측한 결과

| 날짜 및 시험 | 확인 결과 | 적용 가능한 해석 |
|---|---|---|
| 2026년 10월 14일 실제 수집 대조 | 3분 동안 실센서 발행과 저장 3,055건 및 내용 일치 | 해당 센서와 구간의 비교 결과 |
| 2026년 10월 16일 저장 경로 복구 | COLLECTING, rejected 0, 관측 지연 약 0.65에서 1.02초 | 짧은 실제 구간의 관측값 |
| 같은 날 내구 저장 설정 | HDD WAL fsync 10ms 설정 뒤 저장 승인 | 해당 배포의 내구 설정 확인 |
| 저장소 통합 시험 | 원본, 중복, 동일 시각 별도 sequence, 형식 조정과 저장소 중단 및 복구 | 격리 PostgreSQL과 실제 InfluxDB를 사용하는 시험 |

실측 수치는 기존 검증 기록의 날짜와 조건을 유지하여 인용하였다. 3분 대조와 이후 짧은 복구 관측은 서로 다른 시험이며 하나의 장기 시험으로 합산하지 않는다. 지연 범위는 p95나 p99 성능 수용값이 아니다. [1][3]

### 4 2 재현 시험의 구성

`make test-data-store`는 격리된 PostgreSQL, 실제 InfluxDB 2.9.1과 시험용 MQTT 브로커로 저장과 조회를 검증한다. 준비가 없으면 성공으로 건너뛰지 않는다. 기존 운영 센서와 DB를 시험 데이터로 대체하지 않도록 격리 환경을 사용한다.

재현 시 서로 다른 sequence의 동시각 관측, 같은 메시지 재전달, 구형 및 검증 형식의 순서 변경, 저장 실패 뒤 재시도와 조회 조건을 대조한다. 발행, 실제 저장과 API 조회의 건수뿐 아니라 신원과 값을 비교해야 한다. 시험 절차는 TDP-01에 포함한다.

## 5 기여 범위와 운영 조건

### 5 1 개발 기여

자체 개발 범위는 관측 신원에 따른 원본 저장 어댑터, 저장 완료에 연계한 수동 ACK와 연결별 순서 제어, 수용량 제한 및 항목별 동시성, 구형과 검증 관측의 조정, 조회용 논리 비표시 처리이다. MQTT 브로커, InfluxDB 저장 엔진 및 PostgreSQL의 내부 구현은 기반 기술이다.

장애 뒤 결과를 잃지 않는 범위는 저장소의 실제 fsync, 브로커 영속화와 큐, 세션 만료 및 디스크 용량을 함께 만족해야 한다. QoS 1과 완료 캐시만으로 전체 시스템의 exactly once를 주장하지 않는다. 원본 저장, 연속 계산 결과 보관, STREAM의 처리 확인은 각각 다른 계약이다.

### 5 2 한계 및 인수 항목

원본 bucket의 기본 보존 기간은 30일이며 VD 결과는 1일에서 30일의 보존 bucket을 사용한다. 보존 기한 이후의 원본과 승인되지 않은 메시지를 영구 복구하는 기능은 본 범위에 없다. 논리 비표시 이후 남는 물리 필드와 저장 공간은 bucket 보존 정책으로 관리한다. [1]

인수 환경에서는 새 측정 시각의 전진, 실제 저장 증가, 수집 상태와 대기량, 브로커 재시작 및 저장소 중단 후 재전달을 확인한다. health 응답만으로 수집 정상 여부를 판정하지 않는다. 24시간 무손실과 장기 부하, 전체 장애 복구는 PLAN의 잔여 수용 항목이다.
