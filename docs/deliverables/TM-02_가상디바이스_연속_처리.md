## 1 기술 개요와 개발 범위

본 기술은 여러 센서의 검증 관측을 선택하여 연속 계산하고 결과를 가상 센서의 출력으로 관리한다. 공유 eKuiper 엔진과 Processing Agent를 사용하며 가상디바이스마다 별도 SERVICE, supervisor 또는 Pod를 생성하지 않는다. 사용자가 입력 항목과 계산 정의를 등록하면 서버가 제한된 표현식을 검증하고 엔진용 규칙으로 변환한다. [1][2]

개발 범위는 입력 catalog, 원본 연결 및 revision 관리, 계산 표현식 검증과 규칙 생성, 엔진 lease와 generation 제어, 출력 신원 검증, 저장 정책과 웹 조합 등록이다. eKuiper 엔진 자체는 기반 소프트웨어로 사용하였다. 과거 VD v1과 v2의 Runner 실행 및 BATCH 경로는 현재 연속 처리 등록과 구분한다. [3]

### 1 1 주요 기능

| 기능 | 구현 내용 |
|---|---|
| 입력 선택 | 센서와 property, 별칭, 신선도 조건을 명시적으로 선택 |
| 계산 정의 | 제한된 수식과 윈도우 연산을 서버 규칙으로 변환 |
| 조합 등록 | 온도 및 축별 제곱합 10종을 역할별 양식으로 구성 |
| 실행 관리 | 시작, 중지, 설정 변경과 등록 해제 |
| 출력 관리 | 출력별 최신값, 상태, 세대, 저장 이력 조회 |

단순히 엔진이 설치되거나 VD가 등록되었다는 이유로 계산 성공을 표시하지 않는다. 실제 유효 입력, 활성 규칙과 엔진 보고, 현재 generation의 결과가 확인되어야 한다.

## 2 입력 검증과 엔진 조정

### 2 1 처리 흐름

센서 Mapper는 UID, 수집 설정과 세션 순번이 있는 관측을 발행한다. Processing Agent는 현재 허용된 원본과 신선도를 확인하여 공유 엔진으로 전달한다. 서버는 등록 revision에 대응하는 규칙을 만들고 엔진 세대를 부여하며 출력 callback의 소유와 generation을 확인한다. 오래된 규칙이나 옛 세션의 결과가 최신값을 덮어쓰지 않도록 한다. [1]

| 단계 | 입력 또는 상태 | 처리 규칙 |
|---|---|---|
| 원본 선택 | UID, property, 별칭 | 임의 자동 연결 없이 지정한 항목 사용 |
| 정의 등록 | 입력 연결, 계산, 저장 정책 | revision을 검사하고 정의 이력 보존 |
| 실행 준비 | 엔진 소유, lease, generation | 현재 유효 명령과 소유 규칙만 적용 |
| 계산 | 검증 관측과 윈도우 | 타입 및 신선도에 맞는 입력만 사용 |
| 결과 수신 | VD, 출력, revision, generation | 현재 실행과 일치할 때만 최신 결과 확정 |
| 결과 보관 | NONE, SELECTED, ALL | 계산과 독립적으로 보관 대상 결정 |

### 2 2 실행과 정의의 수명

설정 변경은 이전 정의를 덮어쓰지 않고 새 revision과 생성 SQL 템플릿을 보존한다. 공개 API는 임의 SQL과 sink 실행 요청을 받지 않는다. 사용자는 처리 정의와 버전 이력에서 어떤 원본과 계산이 적용되었는지 확인할 수 있다.

등록 해제는 계산 중지와 원본 연결 종료를 요청하고 활성 목록에서 제거한다. 물리 센서와 저장된 결과 및 정의 이력은 보존한다. 엔진 규칙 재생성은 중단 전 윈도우의 자동 복원이나 과거 데이터의 재생과 다르다.

## 3 조합형 등록과 결과 보관

### 3 1 조합 정의

| 조합 구분 | 종류 수 | 계산과 단위 |
|---|---|---|
| 통합 온도 | 1 | 두 온도의 산술평균, 입력과 같은 단위 |
| 온도 편차 | 1 | 첫 온도에서 두 번째 온도를 뺀 값 |
| 회전 제곱합 | 4 | XYZ 또는 XY, XZ, YZ 축 제곱합 |
| 가속도 제곱합 | 4 | XYZ 또는 XY, XZ, YZ 축 제곱합 |

조합 양식은 역할과 축에 맞는 숫자 센서, 동일 단위와 서로 다른 측정 항목을 요구한다. 제곱합은 제곱 단위를 사용한다. 예를 들어 원시 값 3과 4의 평면 제곱합은 25이며 제곱근을 취한 벡터 크기 5와 구분한다. 이 예시는 수식 설명이며 실측 성능 결과가 아니다. 구현은 기존 공통 preset 정의를 Vue 등록 양식에서도 재사용한다. [4]

고급 설정으로 전환해도 현재 입력과 계산식을 이어서 편집한다. 잘못된 축, 누락 역할, 중복 원본과 단위 불일치는 등록 전에 차단한다. 등록 실패 시 입력을 보존하여 오류를 수정할 수 있도록 하였다.

### 3 2 보관 정책과 표시

NONE은 결과 이력을 저장하지 않고 최신 유효값을 제공한다. SELECTED는 지정 출력과 조건을 만족하는 결과를 보관하며 ALL은 전체 출력을 보관한다. 저장 정책은 계산식과 엔진의 출력 자체를 변경하지 않는다. 조건의 value는 계산 결과를 의미한다. [1]

최신 결과의 SKIPPED, PENDING, STORED, EXPIRED는 정책 제외, 저장 대기, 보관 완료, 대기 중 만료를 구분한다. 저장소 장애에서는 최신값 표시와 PostgreSQL 대기열을 분리하고 복구 뒤 선택된 결과를 다시 전달한다. 대기열 상한과 보존 기한을 초과한 데이터까지 무제한 보관하지 않는다.

## 4 구현 및 검증 결과

### 4 1 구현 산출물

Spring의 ContinuousRegistrationService와 ContinuousRuleCompiler는 입력과 계산을 검사하고 등록을 처리한다. ProcessingEngineService와 실행 서비스는 엔진 명령, lease 및 상태를 조정한다. Go Processing Agent는 실제 eKuiper와 입력 및 결과 경로를 연결한다. 공통 preset과 Vue 등록 양식은 같은 계산 정의와 검증 규칙을 사용한다.

### 4 2 시험 기록

| 시험 구분 | 확인 내용 | 범위와 근거 |
|---|---|---|
| 실제 엔진 연동 | MQTT, Agent, eKuiper와 결과 전달, 창 분리 | 실제 eKuiper를 요구하는 처리 시험 [1] |
| 입력 세대 | Mapper session 70회 교체와 옛 session 거절 | 처리 시험에 기록된 조건 [1] |
| 조합 등록 | 10종의 수식, 역할 순서, 단위, 중복과 잘못된 선택 차단 | 2026년 10월 14일 및 19일 회귀 기록 [5] |
| 실제 센서 구성 | 2026년 10월 14일 인프라 구성의 가상디바이스와 출력 관측 | 당시 구성 직후의 제한된 관측 [5] |
| native UI | 조합 요청 보존, 출력 이력 자동 조회, 확대와 오류 보존 | 브라우저 HTTP 경계 회귀 [5] |

2026년 10월 14일 실센서 기반 인프라 구성에서는 기존 정의를 보존하면서 센서별 통계와 조합 계산을 추가하였다. 당시 CPU와 메모리 관측 및 유효 출력이 확인되었으나 최대 동시 실행 용량이나 장기 운영을 수용한 결과로 확대하지 않는다.

2026년 10월 19일 native UI 회귀에서는 조합 10종의 요청 수식과 단위를 대조하고 센서 및 VD 이력의 5초 갱신, 일시정지와 조회 실패 처리를 확인하였다. 이는 공개 UI와 HTTP 경계의 시험이며 실제 모든 센서 조합의 물리 정확도 시험과 구분한다. [5]

## 5 기여 범위와 인수 조건

### 5 1 개발 기여

자체 개발 내용은 센서 관측의 출처와 세대에 기반한 입력 선별, 제한된 계산 정의를 엔진 규칙으로 변환하는 계층, 공유 엔진의 실행 수명 관리와 결과 신원 검사, 조합 양식과 보관 정책 연동이다. 기반 eKuiper의 SQL 엔진과 MQTT 구현, PostgreSQL 및 InfluxDB 자체를 자체 개발 기술로 포함하지 않는다.

소스의 현재 동시 실행 제한은 200 VD와 500 출력이다. 이는 설정 또는 보호 한도이며 해당 수의 실센서 VD가 장시간 정상 처리됨을 입증한 성능 수용값은 아니다. 인수 환경은 입력 빈도, 윈도우와 출력 수에 맞춰 시험해야 한다. [1]

### 5 2 적용 및 미완료 범위

인수 시 qualified 관측을 실제 수신하고 Mapper capability, 세션 순서와 source generation을 확인한다. 엔진 flag는 기본 비활성으로 두고 Agent와 history, 네트워크 및 권한을 준비한 뒤 활성화한다. 되돌리기는 엔진 소유 규칙을 정리하되 물리 센서와 이력 저장소를 보존하는 절차를 따른다.

중단된 윈도우 상태 복원, 모든 과거 원본의 재생, 24시간 손실과 중복 수용, 500 VD 동시 실행은 본 문서의 완료 범위에 포함하지 않는다. 실제 센서의 단위 및 배율 정확도와 센서 간 시간 정렬도 적용 환경에서 확인한다. 실행 및 인수 절차는 TDP-01에 정리한다.
