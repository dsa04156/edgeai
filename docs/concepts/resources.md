# 리소스 모델

EdgeAI는 규격, 실제 자원, 실행 인스턴스를 서로 다른 리소스로 관리합니다.
같은 장비가 여러 화면에 나타날 수 있으므로 어떤 시스템이 원본인지 먼저 확인합니다.

## 프로필

프로필은 재사용할 규격입니다. 발행된 버전의 식별자는 종류·키·버전이며 내용 digest를 보존합니다.
기존 내용을 수정하는 대신 새 버전을 발행합니다. 참조가 없는 버전만 삭제할 수 있습니다.

| 종류 | 정의하는 대상 | 소비하는 기능 |
|---|---|---|
| DEVICE | 이전 입력 장치의 규격. 신규 발행 종료 | 기존 실행 이력의 호환 참조 |
| SERVICE | 실행 이미지·입출력 등 처리 모듈 규격 | Spring DAG |

규격이 저장됐다는 사실만으로 실제 장치 연결이나 이미지 실행 호환성을 보장하지 않습니다.
현재 **실행 모듈 관리** 화면은 SERVICE만 등록·조회합니다. SERVICE는 워크플로에서 실행할 프로그램의 이미지·명령·입출력·자원 설정을 재사용하는 규격입니다.

## 노드와 장치

**노드**는 Kubernetes가 관측하는 실행 자원입니다. 서버와 엣지 디바이스는 명시적인 노드 라벨로
분류합니다. 장비 이름이나 ARM/x86만으로 역할을 추측하지 않습니다.

**센서 디바이스(Device)**는 KubeEdge Device/DeviceStatus CRD를 원본으로 사용합니다. 연결·항목 설정은
DeviceModel/Device CRD로 변환되고 노드·프로토콜별 Mapper를 공유합니다. Physical과 Virtual은 같은
CRD/property 인터페이스를 사용합니다. 과거 VD가 참조했던 장치 신원은 읽기 전용 이력으로 보존합니다.
별도 앱 장치 등록은 종료됐으며, 이전 UUID 장치·세션은 기존 실행 이력을 위한 호환 데이터로만 보존합니다.

센서 화면의 저장 Property 규격은 프로토콜별 항목 설정을 재사용하며 `/api/device-profiles`로 관리합니다.
이 규격과 `/api/v1/profiles/SERVICE`의 버전형 실행 모듈은 다른 리소스입니다.
기존 연결의 항목 추가는 같은 노드·프로토콜·연결 설정을 사용하는 별도 측정 센서와 Device·DeviceStatus CRD를 추가합니다. 공유 Mapper는 재사용합니다.

## 연속 가상 센서

`CONTINUOUS_EKUIPER` VD는 명시적으로 선택한 센서 입력·별칭과 내부 `edgeai.vd/v3` 계산 설정을 보관합니다. VD마다 SERVICE·supervisor·Pod를 만들지 않고 공유 중앙 엔진을 사용합니다. 여러 센서를 한 VD로 조합할 수 있으며 여러 출력은 별도 결과 행·그래프로 표시합니다. 계산 출력의 Device·DeviceStatus CRD는 만들지 않습니다.

센서 등록만으로 가상 센서가 자동 생성되지는 않습니다. 예를 들어 하나의 온도 센서에서 평균·최댓값·경보를 한 등록에 추가하면 VD1개와 결과3행이며, 각각 별도로 등록하면 VD3개입니다. 입력 수와 등록 수를 같은 값으로 세지 않습니다.

센서의 HTTP Virtual 수집 프로토콜은 외부 HTTP JSON endpoint를 읽습니다. 중앙 eKuiper 계산 VD와 구분합니다. 구형 VD 프로필·BATCH·supervisor는 종료됐으며 구형 데이터의 정리와 보존 조건은 [종료 범위](../guides/virtual-devices.md)를 확인합니다.

## 서비스와 워크플로

SERVICE 프로필은 처리 모듈 하나의 규격이고, Spring 워크플로는 모듈들을 연결한 DAG입니다.
DDS 편집기는 별도 경로에서 Kubernetes 배포 구성을 만듭니다. [워크플로 모델](workflows.md)을 확인하세요.
