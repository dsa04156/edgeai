# 센서와 처리를 선택해 가상 장치 만들기

가상 장치 화면에서 **가상 장치 등록**을 열고 장치 키·이름, **센서 선택**, **측정 항목**, **기능**을 차례로 선택합니다. 필터·이동평균·RMS·FFT·임계값을 단계로 조합할 수 있습니다. **처리 파이프라인 추가**로 다른 항목이나 처리 조합을 추가합니다.

처리 표본 수는 실제 서로 다른 관측 시각의 표본 개수입니다. 이동평균·RMS 창 크기와 앞 단계가 줄인 표본 수를 고려하세요. FFT는 남은 표본 수가 2의 거듭제곱이고 수집 간격이 설정한 표본 주파수와 일치해야 합니다. 최대 수신 경과 시간 안에 전체 표본 창이 들어와야 실행할 수 있습니다. Mapper가 적용한 보정값을 사용하며 배율·오프셋을 다시 적용하지 않습니다.

등록하면 서버가 공통 실행 이미지와 불변 SERVICE/VD 프로필을 자동으로 연결합니다. 같은 구성을 여러 장치에 재사용할 수 있습니다. 같은 키·입력의 재시도는 기존 VD를 반환하며, 센서 삭제나 이미지 교체 뒤에도 완료된 등록을 다시 만들지 않습니다. 다른 입력에 같은 키를 쓰면 충돌합니다.

등록 상태와 실행 준비 상태는 별개입니다. 상세에서 **실행 시작**을 요청하고 Runtime 준비 상태를 확인합니다. 기본 실행 위치는 호환 노드에 자동 배치하며 센서의 수집 노드와 달라도 됩니다. 기존 템플릿은 **템플릿으로 등록 · 고급 설정**에서 연결할 수 있습니다.

관리자는 `EDGEAI_PROCESSING_IMAGE`에 발행된 digest를, `EDGEAI_PROCESSING_ARCHITECTURES`에 검증한 아키텍처를 설정합니다. 미설정은 간편 등록을 비활성화합니다. 조회 연결 실패는 별도 오류와 재시도 버튼으로 표시합니다. 사용자마다 새 이미지를 만들 필요가 없습니다.

2026-10-12 개발용 공통 이미지:

```text
192.168.0.56:5000/edgeai/processing-runner@sha256:4223426bcfa7f37e1d23e8bbb6d8f48da962f76869cc9d261230a85eea4b4619
```

이 발행은 Linux amd64에서 빌드하고 실제 컨테이너로 검증했습니다. 서버 아키텍처 설정은 `amd64`로 제한합니다. ARM 센서 수집 원본을 사용할 수 있지만 ARM 노드에서 이 처리 이미지를 실행할 수는 없습니다. ARM 실행 이미지는 별도 native 검증 뒤 추가합니다. 기존 canonical GHCR Runner의 multiarch 릴리스와 운영 GitOps 설정은 변경하지 않습니다.
