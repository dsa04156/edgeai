# 가상 장치 관리

가상 장치는 원본 장치나 실제 실행체가 바뀌어도 같은 ID를 유지하는 논리 리소스입니다.
등록, 실행 시작, 해제, 영구 삭제를 서로 다른 작업으로 취급합니다.

## 템플릿과 인스턴스

VD 프로필은 재사용하는 템플릿이고, 가상 장치 등록은 그 템플릿에 실제 원본 장치와 배치 의도를 연결하는 작업입니다.
프로필은 원본의 규격·허용 출처와 실행할 SERVICE 버전·상태·실행 정책을 정의합니다.

| 종류 | 표현하는 용도 | 현재 원본 조건 |
|---|---|---|
| `sensorMirror` | 물리 센서의 논리적 표현 | 필수 원본 하나 이상 |
| `processing` | 원본 데이터를 처리하는 기능의 논리적 표현 | 필수 원본 하나 이상 |
| `emulation` | 모의 장치·데이터 생성 기능의 논리적 표현 | 원본 없이 등록 가능 |

**VD 기본 양식 채우기**는 `sensorMirror`와 필수 LIVE 원본 조건을 넣습니다.
종류·원본 키·필수 여부·허용 데이터 출처·SERVICE 버전·상태·실행 정책을 작성합니다.
`emulation`을 선택하면 원본 조건을 삭제해 원본 없이 구성할 수 있습니다. EdgeX 센서 목록과 앱 Device 등록은
별개이므로 EdgeX 조회·등록만으로 VD 원본 연결이 만들어지지 않습니다.

## 준비 사항

- 발행된 VD 프로필과 해당 규격이 참조하는 SERVICE 버전
- 원본 슬롯이 필요한 경우 사용할 앱 장치
- 특정 노드 배치라면 유효한 노드 관측
- 실제 실행이라면 VD·Runtime 활성화와 Kubernetes·저장소 설정

전체 워크플로를 먼저 만들 필요는 없습니다. 원본 없는 emulation 규격은 원본 연결 없이 등록할 수 있습니다.

## 1. 등록

**가상 장치 → 가상 장치 등록**에서 키·이름·VD 프로필을 선택합니다.
규격의 원본 키별로 장치를 선택하고 자동 배치 또는 특정 노드를 지정합니다.
장치 선택에는 규격 버전과 데이터 출처가 일치하는 활성 장치만 표시합니다. 선택 원본은 연결하지 않아도 됩니다.
등록 뒤 상세에서 SERVICE 버전, 원본 연결, 배치 의도를 확인합니다.

## 2. 실행 상태 확인

등록 상태 `REGISTERED`는 실행 Ready를 의미하지 않습니다.
실행 패널에서 시작을 요청하고 runtime 세대와 Operation을 확인합니다.
Ready는 Pod 관측과 인증된 supervisor 동작을 요구합니다. API의 요청 수락만으로 Ready를 표시하지 않습니다.

설정을 바꾸거나 실행을 교체할 때는 기존 작업과 이전 실행의 종료를 확인한 뒤 새 세대가 준비됩니다.
동일 Pod를 공유하는 작업 하나를 취소하는 것과 VD 전체를 drain하는 것은 다릅니다.

## 3. 해제

상세에서 **VD 해제 → VD 해제 확정**을 선택합니다. 해제는 더 이상 사용할 등록이 아님을 표시하고
원본 연결·실행 수명에 필요한 정리를 시작합니다. 실행 종료는 별도로 확인합니다.
기존 API `DELETE /api/v1/virtual-devices/{id}`는 이 해제 작업입니다.

## 4. 미사용 등록 영구 삭제

해제된 항목의 **영구 삭제**를 누르고 대상을 확인합니다.
`DELETE /api/v1/virtual-devices/{id}/registration`은 실행·작업 참조가 없는 등록과 닫힌 원본 연결 기록만 삭제합니다.
원본 장치와 프로필은 보존합니다.

완료된 runtime·Operation 이력도 삭제를 막을 수 있습니다. 단순히 Pod가 없다는 이유만으로 삭제할 수는 없습니다.
사용 중이면 409를 반환하고 등록은 유지합니다. 이 기능은 Flyway V43을 포함한 API/DB 조합이 필요합니다.

## 문제 해결

| 증상 | 확인할 내용 |
|---|---|
| 등록할 프로필이 없음 | VD 종류로 발행했는지, SERVICE 참조가 맞는지 |
| 원본 장치 선택 불가 | 앱 장치가 해제되지 않았는지, 필수 sourceKey가 일치하는지 |
| 등록됐지만 실행 안 됨 | VD·Runtime 설정, 실행 Operation과 실제 Pod 상태 |
| 삭제 409 | 활성 연결뿐 아니라 보존할 실행·작업 이력이 있는지 |
