# 가상 센서의 현재 방식과 구형 방식 종료

현재 가상 센서는 선택한 Mapper 측정값을 중앙 eKuiper로 계산하는 `CONTINUOUS_EKUIPER` 방식입니다.
센서 등록만으로 생성되지 않습니다. **가상 센서 → 가상 장치 등록** 모달에서 입력 센서·별칭·계산·출력을 명시적으로 등록합니다. 사용 방법과 운영 활성화 조건은 [연속 센서 계산](vd-processing.md)을 따릅니다.

## 리소스 구분

- 원본 센서는 측정 항목별 Device·DeviceStatus CRD이며 노드의 Mapper가 수집합니다.
- 연속 가상 센서는 내부 `edgeai.vd/v3` 설정과 원본 연결을 갖습니다. 여러 입력을 하나의 VD로 조합하고, 여러 출력은 별도 결과 행·그래프로 표시합니다. 계산 출력의 CRD는 생성하지 않습니다.
- 센서 화면의 `protocol: virtual`은 외부 HTTP JSON endpoint를 읽는 수집 프로토콜입니다. eKuiper 연속 가상 센서와 다른 리소스입니다.

## 종료된 방식

구형 v1/v2 VD 프로필·표본/FFT BATCH·전용 SERVICE·supervisor·자식 Runner·poll API와 워크플로의 VD 실행 정책은 제공하지 않습니다. 일반 SERVICE 워크플로의 AUTO/NODE/REMOTE는 유지합니다. 공개 VD 프로필 발행과 DEVICE 신규 발행도 종료됐습니다.

일반 관리 API의 삭제는 참조 검사로 보호됩니다. 이력이 연결된 등록을 단순 삭제 요청으로 없앨 수 없습니다. 구형 데이터의 일괄 정리는 사용자가 확정한 대상에 대해 DB 백업·별도 복원 검증·참조 관계 분석과 삭제 대상 외 데이터 대조를 거쳐 수행합니다. 적용된 migration·일반 서비스·센서·노드·감사와 백업은 보존합니다.

호스트의 구형 등록·연결 실행 데이터 정리는 완료됐지만 연속 처리의 운영 활성화는 별도입니다. 목록에 남은 시험용 연속 등록을 실제 센서 계산 완료로 해석하지 않습니다.
