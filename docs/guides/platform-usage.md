# 실행 모듈과 센서 디바이스 관리

이 가이드는 규격 발행, 센서 디바이스 관리와 안전한 정리 순서를 설명합니다.
서버·엣지 노드와 KubeEdge Mapper 센서의 관측 목록은 [인프라 연결](infrastructure-inventory.md)에서 다룹니다.

## 준비 사항

API와 DB가 연결된 Dashboard가 필요합니다. 프로필과 장치의 차이는 [리소스 모델](../concepts/resources.md)을 확인합니다.
처음 사용한다면 [첫 프로필 등록](../getting-started/first-profile.md)을 먼저 진행하세요.

## 실행 모듈 등록

SERVICE는 워크플로에서 실행할 프로그램 하나의 설정입니다. 예를 들어 온도 평균 계산이나 AI 추론 프로그램의 이미지·실행 명령·입출력·CPU·메모리 요구량을 저장하고 여러 워크플로에서 재사용합니다. 프로그램 실행은 워크플로에서 요청합니다.

1. **실행 모듈 관리**를 엽니다.
2. **새 버전 등록**으로 모달을 열고 키, `1.0.0` 형태의 버전, 비어 있지 않은 JSON 규격을 입력합니다. ESC·취소·닫기로 돌아가도 초안을 유지합니다.
3. **버전 발행** 후 목록에서 내용과 digest를 확인합니다.

JSON 규격의 최대 크기는 64 KiB입니다. 같은 키·종류·버전의 동일 내용은 기존 발행 결과를 반환하고,
다른 내용은 409로 거절합니다. 변경하려면 새 버전을 발행합니다.
비밀번호·토큰을 프로필에 넣지 않습니다. 저장 성공은 실제 장치나 이미지의 실행 호환성 검사와 다릅니다.

등록한 모듈은 [Spring DAG 가이드](dag-execution.md)에서 선택해 실행을 구성합니다. DDS 배포는 별도의 템플릿을 사용합니다.
기존 DEVICE 프로필 신규 발행은 종료됐으며 이전 실행의 참조 데이터는 보존합니다. Mapper 센서의 저장 규격은 센서 화면에서 관리합니다.

## 센서 디바이스 등록

1. **인프라 관리 → 센서 디바이스 → 새 장치 등록**으로 등록 모달을 엽니다.
2. 대상 Edge Node, 프로토콜, 연결 설정과 측정 항목을 지정합니다.
3. 등록 후 Mapper 준비 상태와 실제 수신 값을 확인합니다.

센서는 KubeEdge Device 이름·UID·DeviceModel로 식별합니다. 별도 UUID 앱 장치 등록은 종료됐습니다.
연결·측정 항목 설정은 [센서 등록](sensor-registration.md)을 따릅니다.

## 수정과 연결 해제

센서 변경은 Kubernetes resourceVersion으로 동시 수정을 보호합니다. 충돌이 나면 최신 상태에서 다시 진행합니다.
연속 VD 원본·종료되지 않은 실행이나 보존한 과거 이력이 참조하는 센서는 기존 참조 보호 규칙을 적용합니다.

## 영구 삭제

| 대상 | 삭제 조건 | 삭제하지 않는 대상 |
|---|---|---|
| 프로필 버전 | 장치·과거 VD·워크플로·실행에서 참조하지 않는 버전 | 다른 버전과 외부 장비 |
| 센서 디바이스 | VD 원본이나 종료되지 않은 실행에서 참조하지 않는 센서 | Kubernetes 노드와 공유 Mapper |

목록의 삭제 버튼에서 대상을 확인합니다. 사용 중이라는 409 응답은 참조를 보호하는 정상 동작입니다.
일상 삭제에서 참조 보호를 우회하지 않습니다. [가상 센서와 구형 방식 종료](virtual-devices.md)에서 사용자에게 명시적으로 승인된 구형 데이터 정리와 일반 삭제의 경계를 확인합니다.

## 결과 확인과 다음 단계

목록을 새로고침해 대상 상태를 확인하고 변경 요청은 **감사 기록**에서 조회합니다.
직접 HTTP 호출은 [API 사용](swagger-ui.md), 서비스 구성은 [워크플로 가이드](workflow-editor-integration.md)를 따릅니다.
