# 프로필과 장치 관리

이 가이드는 규격 발행, 앱 장치 등록과 안전한 정리 순서를 설명합니다.
서버·엣지 노드와 EdgeX 센서의 관측 목록은 [인프라 연결](infrastructure-inventory.md)에서 다룹니다.

## 준비 사항

API와 DB가 연결된 Dashboard가 필요합니다. 프로필과 장치의 차이는 [리소스 모델](../concepts/resources.md)을 확인합니다.
처음 사용한다면 [첫 프로필 등록](../getting-started/first-profile.md)을 먼저 진행하세요.

## 프로필 발행

1. **프로필 관리**에서 DEVICE, SERVICE, VD 중 종류를 선택합니다.
2. **새 버전 등록**에서 키, `1.0.0` 형태의 버전, 비어 있지 않은 JSON 규격을 입력합니다.
3. **버전 발행** 후 목록에서 내용과 digest를 확인합니다.

JSON 규격의 최대 크기는 64 KiB입니다. 같은 키·종류·버전의 동일 내용은 기존 발행 결과를 반환하고,
다른 내용은 409로 거절합니다. 변경하려면 새 버전을 발행합니다.
비밀번호·토큰을 프로필에 넣지 않습니다. 저장 성공은 실제 장치나 이미지의 실행 호환성 검사와 다릅니다.

## 앱 장치 등록

1. DEVICE 프로필 상세의 **장치 등록** 또는 인프라 관리의 앱 등록 장치에서 등록 폼을 엽니다.
2. 프로필 버전, 장치 키, 표시 이름, 데이터 출처를 지정합니다.
3. 등록 후 상세에서 참조한 프로필과 연결 상태를 확인합니다.

장치 에이전트는 세션을 열고 현재 세션의 증가하는 sequence로 관측을 보고합니다.
새 등록만으로 온라인 상태가 되지 않습니다. 실제·재생·합성 출처는 별도로 표시합니다.
EdgeX에 센서를 등록하는 작업과 EdgeAI의 앱 장치 등록은 별개입니다.

## 수정과 연결 해제

장치의 변경은 현재 revision을 기준으로 처리합니다. 동시 수정 충돌이 나면 새로고침 후 최신 상태에서 다시 진행합니다.
해제는 활성 세션과 노드 연결을 종료하며 등록 이력을 남깁니다.
VD 원본으로 사용 중인 장치는 먼저 관련 원본 연결과 실행 종료를 확인해야 합니다.

## 영구 삭제

| 대상 | 삭제 조건 | 삭제하지 않는 대상 |
|---|---|---|
| 프로필 버전 | 장치·VD·워크플로·실행에서 참조하지 않는 버전 | 다른 버전과 외부 장비 |
| 앱 장치 등록 | 활성 연결·세션이 없고 다른 리소스가 참조하지 않는 등록 | Kubernetes 노드와 EdgeX 센서 |
| VD 등록 | 해제됐고 실행·작업 이력이 참조하지 않는 등록 | 원본 장치와 프로필 |

목록의 삭제 버튼에서 대상을 확인합니다. 사용 중이라는 409 응답은 참조를 보호하는 정상 동작입니다.
API가 거절한 삭제를 DB 직접 삭제로 우회하지 않습니다. [가상 장치 관리](virtual-devices.md)에 VD 정리 순서가 있습니다.

## 결과 확인과 다음 단계

목록을 새로고침해 대상 상태를 확인하고 변경 요청은 **감사 기록**에서 조회합니다.
직접 HTTP 호출은 [API 사용](swagger-ui.md), 서비스 구성은 [워크플로 가이드](workflow-editor-integration.md)를 따릅니다.
