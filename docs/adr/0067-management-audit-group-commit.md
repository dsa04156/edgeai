# ADR0067 — 관리 감사의 제한된 동시 커밋

상태: 미채택, 2026-10-04. 아래는 실험한 설계이며 제품은 ADR0066의 개별 트랜잭션을 유지한다.

동시성/영속성 시험은 통과하고 감사 transaction 수는 줄었지만, 기본 전체 부하의200건과
180초 지속 부하의374건 미발송을 해결하지 못했다. DB commit/WAL 대기를 직접 관측했고
단일 writer의 대기와 묶음 전체 실패라는 복잡성을 추가할 만큼 안정성 개선을 입증하지 못했다.
실험 구현은 비공개 작업 자료에 보존하고 서비스 변경은 되돌렸다. 이 결정은 기존 부하 실패를
해결했다는 뜻이 아니며, DB 지연과 합의 성능 수용은 계속 남는다.

후속 [동기화 빈도·20ms 비교](../evidence/m8-audit-storage-diagnostics.md)는 별도 작업 복사본의
측정이다. 비계측 지속 부하는 통과했으나 공유 호스트 변동과 진단 기록 경계의 영향을 구분하며,
이 문서의 미채택 상태나 제품 저장 방식을 변경하지 않는다.

감사 추가 후 같은100→300→1,000대 관리 부하에서 첫 실행은108건을 발송하지 못했다.
같은 설정 진단은 전부 처리했지만 p95 228.13ms와 실제 JDBC/WAL 대기를 관측했다.
지연이 큰30–40초 구간과 BCrypt 실행 표본이 집중된15/45초 구간은 일치하지 않았다.
첫 실패 원인을 단정하거나 공유 PostgreSQL의 fsync/synchronous_commit을 끄지 않는다.

동시 관리 감사 요청의 접수/결과 INSERT를 최대64개 명령의 한 transaction으로 묶는다.
첫 요청은 최대2ms를 모으고, 이미 실행 중인 transaction 동안 들어온 요청은 다음 묶음이 된다.
대기 queue는512개로 제한한다. 가득 차면 접수는 실행 전503, 결과는 미확정으로 남는 기존
실패 경계를 따른다. 조회401/403의 접수와 결과는 하나의 명령으로 같이 저장한다.

요청 스레드가 한 묶음만 처리한 뒤 다음 호출자에게 진행을 넘긴다. 별도 executor/영속성 없는
백그라운드 성공 응답은 없다. 각 호출자는 자기 명령이 포함된 DB transaction의 실제 commit
이후에만 성공한다. 묶음은 도메인 transaction과 분리된 REQUIRES_NEW다. 서비스 메서드에서
connection을 확보한 채 기다리지 않아 다섯 개 pool을 기다리는 요청들이 점유하지 않는다.
호출 중 interrupt는 commit/rollback 결과를 확인한 뒤 복구한다. 이전 도메인 동작과 HTTP
결과 의미·서버 UUID·불변 DB·현재 Basic 주체·비밀값 제외 정책은 바꾸지 않는다.

INSERT 또는 commit 실패는 해당 묶음 전체에 실패를 전달한다. 자동 재실행하지 않으며 다음
묶음은 계속 처리할 수 있다. 한 요청의 저장 오류가 같은 묶음의 다른 요청도 거절할 수 있다는
가용성 경계를 명시한다. process 유실 전 commit하지 않은 접수는 성공한 것으로 응답하지
않으며, 이미 도메인이 실행된 결과의 유실은 기존 OUTCOME_UNKNOWN으로 나타난다.

실험의 commit 전 응답 금지·묶음 rollback/복구·interrupt·예외와 실제 PostgreSQL 정합성은
검증했다. [부하 실패와 근거](../evidence/m9-audit-group-commit.md)를 함께 보존한다.
