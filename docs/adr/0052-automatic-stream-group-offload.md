# ADR 0052: 측정 기반 STREAM 그룹 자동 전환

2026-10-04. ADR0009의 선택적 자동 전환을 ADR0051의 STREAM 체크포인트 인계에 연결한다.
실제 Kubernetes 자원 측정·배치와 새 완성 이미지 수용은 별도 게이트다.

## 판단과 그룹 전환

공개 Run의 기존 `offload` 정책을 사용한다. 일반 SERVICE는 RESTART, STREAM SERVICE는
CHECKPOINT 복구를 선언해야 한다. 같은 DAG의 일반 작업이 복구를 선언하지 않았으면
Run 생성 전에 거절한다. STREAM의 REMOTE/VD 대상 제한은 유지한다.

기존 현재 producer 인증, 연속 측정·시간·sequence·자원 제한 검증과 호환 READY 노드
확인을 재사용한다. STREAM은 연결된 모든 작업의 현재 외부 체크포인트·경로·lease와
완료 허가 전 상태를 추가 확인한다. 준비되지 않은 그룹은 아무 작업도 차단하지 않고 다음
측정 판단으로 미룬다. 일반적인 미준비 오류는 같은 트랜잭션 서비스 안에서 처리하고 DB
오류는 숨기지 않는다.

선택된 작업의 표본은 모든 구성원의 시작 대기와 이전 전환 대기가 끝난 시각 이후여야 한다.
전체 구성원의 자동 전환 예산과 수동/자동 합계8회 제한을 검사한다. 함께 재개하는 작업도
동일 Operation을 이력에 기록하고 자동 전환 횟수를 소비한다. 같은 Run 잠금에서 판단
근거·불변 구성원 계획을 저장한 뒤 전체 producer와 경로를 차단하므로 동시 압력 판단은
그룹 전환을 중복 생성하지 않는다.

선택된 작업은 방문한 모든 노드를 제외한 AUTO로 바뀐다. 나머지 작업은 기존 AUTO/NODE와
제외 노드를 유지한다. ADR0051의 전체 물리 종료·브로커 권한 회수 장벽, 새 OFFLOAD Attempt,
그룹 전체 claim, 외부 체크포인트 및 Device journal 인계를 그대로 사용한다. 독립 분기와
BATCH 결과 대기·취소·retry의 의미를 변경하지 않는다.

V28은 V27의 구성원 보호 함수를 교체한다. 정책을 갖춘 자동 Operation을 허용하면서
선택 구성원의 원본/대상/제외 노드가 부모 판단과 일치하고, 다른 구성원의 배치가 원래
Attempt와 같으며, 자동 판단에 저장된 정책이 Run 정책과 같아야 한다. 기존 인계 불변성·
종료·회수 제약은 보존한다. V1–V27은 수정하지 않는다.

## 실제 측정 경로

기존 Runner는 최종 파일 생성 단계에서만 측정해 스트리밍 계산 중 표본이 없었다.
한 측정 세션을 스트리밍 계산부터 최종 처리까지 유지하여 같은 Attempt의 sequence가
초기화되지 않게 한다. 실제 자기 cgroup v2와 기존 workload 측정 파일을 읽으며 없는
값이나 무제한 quota를 추측하지 않는다. 측정 서버의 일시 장애는 계산 실패로 바꾸지 않지만
producer 권한 거절은 스트리밍 계산과 최종 처리를 종료시킨다. 종료 시 측정 스레드를
회수하고 업로드·결과 확정은 기존 권한 검증을 유지한다.

## 검증 범위

[실행 근거](../evidence/m7-stream-automatic-offload.md)에 DB 동시성/보호 조건, 실제
Runner·HTTPS 측정과 서버/S3/브로커의 체크포인트 인계, UI·계약 검증을 기록한다.
서버 인계 시험의 Pod 신원·노드 배정·종료 관측과 workload 지연 입력은 명시적 fixture다.
실제 메모리/CPU 부하에 따른 Kubernetes 이동, 새 이미지 CI/배포, VD/단계별 배치와 외부
장치·성능 수용은 이 ADR의 로컬 검증으로 완료 처리하지 않는다.
