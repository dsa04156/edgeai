# 기존 가상 디바이스 기능 제거

날짜: 2026-10-12. 상태: 결정.

## 요구사항과 근거

사용자는 eKuiper 설치에 맞춰 가상 디바이스를 새로 구성할 계획이며,
삭제 범위를 “기존 가상 디바이스 기능 전체만 삭제”로 확정했다.
이 작업은 기존 구현 제거까지다. 새 eKuiper 연동이나 실행 계약은 아직 정하지 않았다.

## 결정

- 가상 장치 등록·원본 연결·VD 프로필 양식과 계약·실행 수명 관리·poll·배정·supervisor·전용 API를 제거한다.
- 메뉴·현황 카드·워크플로의 VD 실행 선택·전용 배포 설정·데모와 현재 VD 수용시험을 제거한다.
- DEVICE/SERVICE 프로필, 앱 장치, KubeEdge Mapper 센서, 노드, DDS/Spring 워크플로, 일반 Runner·NODE/REMOTE 실행과 결과 관리를 보존한다.
- 적용된 Flyway migration과 기존 DB·결과 파일·감사 기록은 삭제하지 않는다.
  공유 모델의 과거 VD 식별자와 DB 참조 보호, 오프라인 백업·복구 판독은 과거 이력 호환성으로 유지한다.
- 과거 VD 실행은 NODE/REMOTE로 전환된 작업도 새 배정·Runner 인증·재시도·offload 대상으로 허용하지 않는다.
  기존 NODE/REMOTE 물리 실행의 취소·종료 확인과 결과·고정 입력 이력 조회는 유지한다.
  기존 버전의 활성 supervisor는 업그레이드 전에 기존 버전에서 종료해야 한다.

## 검증 경계

로컬 단위·계약·대시보드·격리 PostgreSQL 검증 결과는
[검증 기록](../evidence/virtual-device-removal-2026-10-12.md)에 기록한다.
사용자의 후속 “ㄱㄱ”에 따라 검증된 API·대시보드와 기존 CI/GitOps 배포에 반영한다.
호스트 DB의 적용 migration 53개와 체크섬을 대조했다. V49~53도 이미 적용된 파일 그대로 보존한다.
클러스터 DB는 기존 V1~48의 체크섬을 유지하며 V49~53으로 정상 업그레이드했고, 도메인 데이터 건수는 동일하다.
사용자 DB의 기존 데이터와 설치 중인 eKuiper·센서 설정은 삭제하거나 변경하지 않는다.
과거 VD 실행 프로토콜을 사용하는 Kubernetes 복구 수용시험은 기존 버전용 기록이다.

## 후속 연속 센서 처리 계약 (2026-10-13)

사용자의 새 센서·여러 입력 프로토콜을 고려한 eKuiper 설계 구현과 PR 병합 요청에 따라,
`edgeai.vd/v3 / CONTINUOUS_EKUIPER` 등록·공유 엔진 실행·출력별 이력 API를 별도로 제공한다.
VD마다 SERVICE/supervisor/Pod를 생성하지 않고 명시적으로 선택한 Mapper 센서 항목을 사용한다.
내부 v3 설정과 연결 이력만 기존 영속 테이블을 재사용한다. 과거 v1/v2 등록은 새 목록·상세·실행에서 제외한다.
공개 VD 프로필 발행, 기존 일반 VD 등록·BATCH·poll·Runner 실행 정책은 제거된 상태로 유지한다.
DEVICE 프로필 신규 발행 종료와 일반 SERVICE·AUTO/NODE/REMOTE 정책도 유지한다.
적용된 migration은 수정하지 않는다. 기능 기본값은 비활성이고 운영 Agent·history 배포와 수용시험은 별도다.

## 명시적 구형 등록 데이터 정리 (2026-10-13)

구현 제거 당시에는 기존 DB를 보존했다. 이후 사용자가 웹에 남은 구형 등록을 확인하고 이전 방식의 삭제를 명시적으로 요청했다. 이 후속 요청은 구형 VD 등록·프로필·연결된 실행 데이터의 정리를 승인하며, 실제 센서와 연속 v3 등록·일반 서비스의 보존 범위를 변경하지 않는다.

호스트 관리 DB 전체를 백업하고 별도 inactive DB에 복원해 참조 관계에 따른 삭제를 먼저 검증했다. 실제 적용은 하나의 트랜잭션으로 수행하고 FK는 활성 상태를 유지했다. 변경 대상의 사용자 trigger는 잠금 안에서만 일시 해제하고 원래 상태로 복구했다. 삭제 대상 밖의 행은 적용 전후 동일성을 대조했다. 일반 워크플로 정의·SERVICE/DEVICE 호환 데이터·노드·센서·감사·적용된 migration과 백업은 보존한다. 이 절차는 일상 API의 참조 보호를 우회하는 일반 삭제 기능이 아니다.

현재 웹/API는 구형 supervisor 등록을 노출하지 않는다. 남은 연속 처리의 시험용 등록을 실센서 계산 완료로 간주하지 않는다. 운영 flag는 false이며 실제 Agent·history 활성화는 별도다. 최신 사용법·구성·다음 게이트는 현재 가이드와 PROGRESS/PLAN을 기준으로 하고, 아래·이전 날짜의 구형 수용 기록은 역사적 근거로만 해석한다.
