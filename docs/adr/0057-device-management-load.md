# ADR0057 — 실제 API·PostgreSQL 장치 관리 부하 측정

2026-10-04. M8의 측정 계약이며 M8 완료나 실장비 성능 수용 판정이 아니다.

Notion 전체 설계·API·ERD·실행 지시를 다시 읽었다. 네 문서의 수정 시각은 기존
`docs/sources.md`와 동일하다. 원문은 100→300→1,000 장치 관리 부하, 실제 Remote 계약 및
성능 수치의 별도 확정, 외부 항목이 남아 있어도 독립 단계를 진행하도록 요구한다.
M5/M7의 외부 수용·Remote STREAM·VD 자동 전환을 완료 처리하지 않고 M8을 병행한다.

`scripts/test-load.sh`는 새 이름의 전용 PostgreSQL DB와 loopback API 프로세스를 만든다.
기존 DB·API·클러스터에 부하를 보내지 않는다. JVM heap512MiB·기본 Hikari pool5, 동일 JAR과
실제 DB 버전·호스트 CPU 수·메모리 및 비격리 환경을 보고한다. API CPU/RSS와 해당 DB의
크기·연결·deadlock 통계를 측정한다. 호스트 공유 PostgreSQL의 CPU를 전용 DB CPU로 표시하지 않는다.

누적 장치100→300→1,000개를 공개 API로 등록하고 SYNTHETIC 세션을 연다. 기본60초씩,
장치당10초마다 관측을 보내고 관측10개당 상세 조회1개를 함께 보낸다. warmup은 측정에서 분리한다.
장치 수와 RPS를 구분하며 제시 부하는 각각 관측10/30/100RPS + 조회1/3/10RPS다.
발송 시각을 미리 고정하고 동시 요청/대기열을 제한한다. 느린 응답 때문에 다음 발송을
뒤로 밀지 않으며, 누락·발송 지연·전송 시간·예정 시각부터 응답까지의 지연을 따로 기록한다.
오류를 자동 재시도로 숨기지 않는다. 실제 지연 표본과 p50/p95/p99, 처리량·오류·누락을 보존한다.

각 단계 뒤 페이지 전체 조회, 최신 session/sequence, 실제 DB 관측 수·내용·중복 부재를 대조한다.
일부 장치의 동일 관측/boot 재전송, 새 세션, 이전 세션 거절을 확인한다. 마지막에 전용 API를
종료하고 소유 DB만 삭제한다. 실패도 부분 report와 비공개 API 로그를 남기고 정리한다.

합의된 성능 수치는 아직 없다. 기본 명령은 측정 뒤 exit2/PENDING_ACCEPTANCE를 반환한다.
`--measure-only`는 명시적인 측정·정합성 범위가 통과하면 exit0이며 성능 수용은 주장하지 않는다.
`--max-p95-ms`는 실행자가 제공한 예정 시각 기준 지연 예산을 보고서에 고정하고 검사한다.
빠른 소수 장치 검사는 전체100/300/1,000 수용과 구분한다. 실제 장치·MQTT 데이터·모델 계산·
UI/클러스터 확장 성능은 이 관리 HTTP 부하로 대체하지 않는다.
