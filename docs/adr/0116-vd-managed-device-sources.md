# 0116 — 별도 앱 장치 등록 종료와 VD 센서 원본 전환

날짜: 2026-10-08. 결정: 채택. 사용자가 등록 장치를 제거하고 VD를 센서 디바이스로 옮기도록 요청했다.

센서 디바이스가 이미 KubeEdge 신원·모델·연결 상태를 갖고 있으므로 앱 UUID 장치를 재등록하지 않는다.
등록 장치 탭과 VD의 DEVICE/원본 장치 등록 폼을 제거하고 앱 장치 생성 API는 410을 반환한다.
기존 장치·세션·STREAM 실행 이력을 삭제하거나 새 KubeEdge 이름으로 암묵적으로 변환하지 않는다.

v2 VD 템플릿의 원본 슬롯은 DeviceModel과 필수 여부를 선언한다. VD 인스턴스는 KubeEdge 이름을 선택하고
서버가 UID와 모델을 검증·고정한다. 같은 모델의 Physical/Virtual 장치를 함께 사용할 수 있으며 프로토콜은
Mapper가 담당한다. 오프라인 상태는 신원 등록을 막지 않으며 실행 준비와 수신 상태를 동일시하지 않는다.

VD 수정은 새 템플릿 UUID를 받을 수 있다. 생성 digest와 VD ID, 과거 원본·Runtime 이력은 유지하고
revision으로 동시 수정을 차단한다. 바뀐 UID·모델·원본은 기존 binding을 닫고 새 binding을 만든다.
Flyway V44는 기존 UUID 열을 호환 이력으로 보존하면서 새 센서 이름·UID·모델 열과 검사를 추가한다.
V45는 템플릿 교체 후 유지된 활성 binding까지 최종 트랜잭션 상태에서 검증한다.
v1 템플릿은 호환 읽기·기존 실행 경로를 유지하며 새 화면에서 v2로 명시적으로 전환한다.

VD 연결과 센서 변경은 센서 이름 순서로 PostgreSQL 트랜잭션 잠금을 공유한다.
VD가 참조하는 센서의 삭제·모델 변경은 관리 API에서 409로 차단한다. 클러스터 외부 변경은 막을 수 없으므로
실행 시작·교체 시 UID/모델을 다시 확인한다. 연속 MQTT→VD consumer 자동 구성은 이 변경에 포함하지 않는다.

사용자는 수신 이력이 없는 실습 VD와 앱 등록 장치를 테스트 데이터로 확인하고 삭제를 승인했다.
실제 Arduino/Sense HAT 센서에는 원본을 추측해 연결하지 않는다.
