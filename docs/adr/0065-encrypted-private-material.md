# ADR0065 — 정적 복구 파일의 암호화 백업과 새 경로 복원

상태: 채택, 2026-10-04. M9의 Secret·CA 파일 복원 구성 요소다.

## 결정과 범위

선택한 정적 파일을 `relative-name=source-path`로 명시한다. 디렉터리를 재귀 탐색하거나
클러스터 Secret을 자동 수집하지 않는다. 백업에는 공개 수신자만 필요하며 복호화 개인 키는
별도로 보관한다. 새 출력 디렉터리만 허용하고 원본 파일과 운영 설정을 덮어쓰지 않는다.

암호화 구현은 공식 [age v1.3.2](https://github.com/FiloSottile/age/releases/tag/v1.3.2)를
사용한다. Linux amd64/arm64 배포 archive SHA256을 코드에 고정하고 설치할 두 정규 파일만
읽는다. 매 실행 때 archive와 설치 파일을 대조하며 다른 파일을 자동 교체하지 않는다.
캐시/설치 디렉터리의 링크는 거절한다. 실제 로컬 실행 근거는 amd64이며 arm64 실행은 후속이다.
파일 형식은 [age 사양](https://c2sp.org/age)을 따른다. 자체 암호 알고리즘은 구현하지 않는다.

원본은 현재 사용자 소유·다른 사용자 접근 권한 없음·정규 파일·링크 수1을 요구한다.
최대1,024개, 파일당16MiB, 합계256MiB다. 열린 descriptor를 유지하며 읽기/암호화 후 inode,
크기, 변경 시각, 권한과 현재 경로를 대조한다. 변경된 입력은 성공 manifest를 발행하지 않는다.
이는 정적 파일의 일관성 확인이며 여러 서비스가 쓰는 journal의 일관된 스냅샷이 아니다.

파일 이름·길이·SHA256·bundle ID를 내부 manifest에 넣고 파일들과 함께 암호화한다.
외부 manifest는 암호문 checksum/길이, 공개 수신자, 개수/총크기와 식별자만 보존한다.
파일 이름과 비밀값은 외부 보고서에 넣지 않는다. 임시 평문은 권한0700 디렉터리와0600
파일에 두고 성공/실패 후 제거한다. 비정상 강제 종료·호스트 유실 시 잔여 파일과 매체의
보안 삭제까지 보장하지 않으므로 복구 작업 경로의 저장 매체도 보호해야 한다.

## 복원 검증과 경계

native X25519/PQ 개인 키 파일 하나만 허용한다. 플러그인·SSH identity·암호문 형태의
identity는 사용하지 않는다. 키는 명령행 값이나 로그로 전달하지 않고 상속한 descriptor로
공식 도구에 전달한다. 개인 키의 공개 수신자가 manifest와 같은지 확인하고 인증 복호화한다.

내부 archive의 중복/추가 entry, 경로 이탈, 파일과 디렉터리 충돌, 압축·링크·비정규 파일,
길이·SHA·bundle ID 불일치를 모두 검증한 후에만 `files/`로 게시한다. 파일0600/디렉터리0700을
사용하며 원래 권한을 그대로 복원하지 않는다. 기존 목적지는 거절한다.

성공은 `RESTORED_PRIVATE_FILES_ONLY`, `activated=false`, `originAuthenticated=false`다.
수신자 공개 키로 암호화했다는 사실은 백업 작성자의 서명이 아니다. 신뢰하는 위치에서 받은
백업/manifest를 사용해야 하며, 이 구성 요소는 작성자 인증이나 운영 키 활성화를 증명하지 않는다.
동일 사용자나 관리자가 작업 경로/도구를 병행 변경하는 환경은 지원 범위 밖이다.

운영 Secret·CA 목록과 버전 매핑, 오프사이트 보관·일정·키 회전/전달, 서명 정책,
broker·장치 journal, DB/S3와의 결합 복원 및 서비스 재활성화가 남는다.
