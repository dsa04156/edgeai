# 접근과 요청 보호

현재 작업 트리의 Dashboard와 일반 관리 API는 로그인 계정을 요구하지 않습니다.
이 문서는 현재 코드의 요청 경계를 설명하며 실행 중인 오래된 배포가 같은 설정이라는 뜻은 아닙니다.

## 관리 요청

일반 관리 API의 조회는 계정 인증 없이 접근합니다. 변경 요청에는 CSRF 토큰과 세션 쿠키가 필요합니다.
CSRF는 다른 사이트에서의 의도치 않은 요청을 제한하는 장치이며 사용자별 권한 관리가 아닙니다.
Dashboard 프록시는 허용 경로·메서드와 고정 upstream을 사용합니다.

Dashboard 또는 API에 접근 가능한 사용자는 관리 기능을 사용할 수 있습니다.
신뢰되지 않는 네트워크에 노출하려면 별도 접근 계층과 운영 권한 정책을 준비해야 합니다.
현재 사용자별 identity/RBAC의 전체 수용은 완료되지 않았습니다.

## 내부 실행 요청

Runner, VD, Device 스트림 경로는 별도의 서명·토큰·실행 신원 계약을 사용합니다.
일반 관리 경로가 열려 있다고 내부 실행 API까지 인증 없이 허용되는 것은 아닙니다.
브라우저에서 내부 프로토콜을 직접 호출하는 방식으로 통합하지 않습니다.

## 외부 서비스 자격 증명

Gitea·Argo CD·레지스트리·DB·broker 키는 해당 서버 환경에 둡니다.
프로필 JSON이나 `NEXT_PUBLIC_*`에 비밀번호·토큰을 넣지 않습니다.
Swagger의 직접 변경 요청은 실제 DB에 반영되므로 대상을 확인합니다.

## 감사와 복원 점검

감사 기록의 주체는 실제 인증 정보를 기준으로 하며 현재 익명 관리 요청을 로그인 사용자로 추정하지 않습니다.
과거 `LOCAL_BASIC` 기록은 당시 사용된 계정 기록입니다.
복원 DB의 조회 전용 모드는 쓰기를 거절하며 내부 worker도 별도로 차단합니다.
